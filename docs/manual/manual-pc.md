# KudagiTune 説明書（PC 版）

対象の版：KudagiTune 1.0.0
旧称は playlist-sync-fox です。設定・ログ・鍵のフォルダ名と、ログイン時の起動の登録名は旧称のままです（下の「データの置き場と削除」）。

## できること

- PC の iTunes のプレイリストを、Android 端末へ同期します。
- PC のアプリはサーバーとして動きます。端末が PC に取りに行きます。
- PC のアプリはトレイに常駐します。曲の変換や iTunes への書き戻しはしません。
- 同期の開始は端末の操作です。手動の同期と、従量制でないネットワークにつながっている間に端末が周期で起動する自動の同期があります。

## 動作環境

| 項目 | 内容 |
|---|---|
| OS | Windows 11 |
| iTunes | iTunes 12.x（Windows 版）。Apple Music アプリは未対応です |
| ネットワーク | 同一 LAN、Tailscale、USB テザリング、Bluetooth テザリングのいずれか |

## 導入

GitHub の Releases に、インストーラー（MSI）と zip の 2 つがあります。中身は同じです。ふつうはインストーラーを使ってください。新しい版は Releases で確認してください（アプリの中では更新を確認しません）。

### インストーラー（MSI）

1. `KudagiTune-<版>.msi` をダウンロードして実行します。
2. コード署名をしていないため、SmartScreen の警告が出ます。「詳細情報」→「実行」を押します。
3. 管理者の確認（UAC）が出たら「はい」を押します。`C:\Program Files\KudagiTune` に入り、スタートメニューに「KudagiTune」が追加されます。
4. スタートメニューから KudagiTune を起動します。メインの窓が開き、トレイにも入ります。窓を閉じても、アプリはトレイで動き続けます。

更新するときは、トレイのメニューの「終了」でアプリを止めてから、新しい版の MSI を実行します。設定とペアリングはそのまま引き継がれます。

### zip

管理者の権限が無い PC では zip を使います。

1. `KudagiTune-<版>-windows.zip` をダウンロードして、好きなフォルダに展開します。Java の実行環境が同梱されているため、Java の導入は要りません。
2. 展開したフォルダの `KudagiTune\KudagiTune.exe` を起動します。SmartScreen の警告が出たら「詳細情報」→「実行」を押します。

「ログイン時に起動」は既定で有効です。ログイン時の起動では、窓は開かずトレイだけに入ります。ただし初回は、ログイン時の起動でも窓が開きます。端末の自動の同期は、PC のアプリが動いていることが前提です。

すでに起動しているときに、もう一度実行ファイルを起動すると、2 つ目はすぐ終わり、1 つ目のメインの窓が開きます（1 秒ほどかかります）。アプリは 1 つしか動きません。

## iTunes の設定

PC のアプリは、iTunes が出力する XML（iTunes Music Library.xml）を読みます。

1. iTunes の「編集」→「環境設定」→「詳細」を開きます。
2. 「iTunes ライブラリ XML をほかのアプリケーションと共有」（英語版では「Share iTunes Library XML with other applications」）の項目を有効にします。日本語の項目名は実物で確かめていません。見つからないときは、英語名に当たる項目を探してください。
3. 窓の「設定」の「XML の場所」を確認します。未設定のときは、実際に読んでいる既定のパス（`%USERPROFILE%\Music\iTunes\iTunes Music Library.xml`）が欄に入っています。iTunes 12.13.7.1 ではこの場所でした。ほかの版では違う場合があるので、読めないときは手で指定してください。
4. 「確認して保存する」を押すと、指定した場所が読めるか検査されます。読めなければ「この場所の XML を読めません」と出て、保存されません。

iTunes を起動してライブラリを変えると、XML が更新されます。

## プレイリストの選択

同期するプレイリストは、PC ではなく端末のアプリで選びます（端末の説明書の「プレイリストの選択」）。PC の画面にはプレイリストの一覧もチェックボックスもありません。

- PC は、端末が選んだプレイリストの曲だけを配ります。選んでいない曲は配りません。
- PC の設定ファイルには選択を保存しません。古い版の設定ファイルに選択が残っていても、読み捨てます。
- PC の画面に出るのは、ペアリング、状態、XML の場所、ログイン時の起動、ライセンスだけです。

## ペアリング

初回だけ、PC と端末を結び付けます。

1. トレイのメニューの「ペアリングコードを表示」を選びます（窓の「ペアリング」の「コードを表示」でも同じです）。窓が開き、ペアリングコードが出ます。端末をペアリング済みのあいだは、どちらも押せません。先に PC の窓の「端末」で解除してください。
2. 端末のアプリでペアリングを始めます。
3. PC の画面に出た 6 桁の「ペアリングコード」を、端末に入力します。ペアリングコードは通信には流れません。
4. 両方の画面に「確認コード」が出ます。同じかどうか見比べてください。PC の確認コードは、コピーのボタンでクリップボードへ写せます。確認コードは PC の公開鍵のハッシュです。端末には、コードを送って PC から応答が返った時点で出ます。端末への保存は、ペアリングが成功した時点で確定します。違う場合は、窓の「端末」の「ペアリングを解除する」と端末の設定の両方で解除してから、もう一度ペアリングしてください。

ペアリングコードには有効期限があります。期限が切れた後、または使った後は無効になり、新しいコードは操作するまで出ません。「コードを作り直す」で作り直せます。「閉じる」でコードを無効にできます。失敗が上限を超えると、そのコードは無効になり、しばらく作り直せません。窓を閉じても、コードは無効になります。

### 接続先

ペアリングの画面には、端末が接続する先が表示されます。

| 接続方法 | 手順 |
|---|---|
| 同一 LAN | 端末が自動で PC を見つけます。見つからないときは、画面の「接続先の一覧」の IP とポート（例：192.0.2.10:47800）を端末に手入力します |
| Tailscale | Tailscale のアプリで PC の名前（MagicDNS 名）を見て、端末に手入力します。PC の画面には、MagicDNS 名は表示されません（PC は名前を取得しません） |
| USB テザリング | 端末のテザリングを有効にします。端末が PC を見つけられなければ、画面に別行で出るテザリング側の IP を端末に手入力します |
| Bluetooth テザリング | 端末と PC を Bluetooth でペアにし、端末の「Bluetooth テザリング」を有効にしたうえで、Windows の「Bluetooth とデバイス」から端末の「アクセス ポイント」に接続します。あとは USB テザリングと同じです。転送は大幅に遅く、端末側の自動の同期は通常は動きません。PC がこの接続でインターネットに出ると端末のモバイル回線を使います |

### 端末を入れ直したとき

端末のアプリを入れ直すと、古いペアリングが PC に残ります。

1. 窓の「端末」で「ペアリングを解除する」を押します。
2. もう一度、上の手順でペアリングします。

端末側で解除する場合は、端末の操作で行います。

## 画面の見方

### メインの窓

窓は 1 枚です。窓の題は KudagiTune です。窓の上は Windows のタイトルバーで、アプリ独自の帯はありません。配色は Windows のアプリのモード（ライト・ダーク）に合わせて切り替わります。

| 場所 | 内容 |
|---|---|
| 左の欄 | 上から、警告、iTunes ライブラリ（XML の状態）、端末、ペアリング、設定 |
| 左の欄の iTunes ライブラリ | 次のどれかが出ます。「XML を確かめています」（まだ読んでいない間。起動直後など。緑ではなく薄い文字の色）、緑の「XML を読み込めています」、「XML が N 日更新されていません」、赤字の「XML を読めません。…」（iTunes の共有の設定を、日本語名と英語名の両方で案内します） |
| 右の上（同期の進行状況） | 同期中は「同期中」と出て、全体の棒（端末が知らせる割合、曲数、容量）と、PC が送っている曲の棒（曲のファイル名、割合、容量）が出ます。同期していないときは状態だけが出ます |
| 右の下（ログ） | PC のログの新しい行が下に流れます。時刻、レベル、種類、内容の順です。上へ送って読んでいる間は流れを止めます。「ログの場所を開く」でログのフォルダを開きます。アプリを起動してからの分だけ出ます |
| 最下段の帯 | トレイと同じ状態の表示、ポート、端末の台数 |

- 全体の割合は、端末が同期の間に PC へ知らせる進み具合です。端末から知らせが 30 秒届かないと、全体の棒は消えます。端末が同期を終えて結果を報告したときにも消えます。

### トレイ

トレイのアイコン（同期の輪に狐の耳と尻尾の図柄）の左クリックで、メインの窓が開きます。

アイコンにマウスを合わせると、「KudagiTune：待機中」のように、「KudagiTune：」に続けて状態が文字で出ます。メニューには状態の項目はありません。下の表の「表示」の列は、「KudagiTune：」に続く部分です。

| 表示 | 内容 |
|---|---|
| 鍵の保管に失敗しました | 鍵を読み出せないため、サーバーが起動していません |
| サーバーを起動できません | 鍵の保管の失敗以外の理由（ポートの使用中、証明書の用意の失敗など）で、サーバーが起動していません。ログを確かめてください（下の「困ったとき」） |
| ペアリングしていません | 端末が登録されていません |
| XML を読めません | iTunes の XML を読めていません |
| 同期中 | 端末が曲を取りに来ています |
| 待機中 | 上のどれでもありません |

- 同期の件数は出ません。進み具合は窓の「同期の進行状況」で見てください。
- 警告があるときは、表示の末尾に「（警告あり）」が付きます（例：「KudagiTune：待機中（警告あり）」）。警告の中身は、メインの窓の左の欄の上で見てください。

メニューには次の項目があります。

| 項目 | 動作 |
|---|---|
| 開く | メインの窓を開く |
| ペアリングコードを表示 | ペアリングの画面を開く。ペアリング済みのあいだは押せない |
| 設定 | メインの窓を開く（「開く」と同じ。設定は窓の左の欄の「設定」にあります） |
| ログの場所を開く | ログのフォルダをエクスプローラで開く |
| 終了 | サーバーを止めて終了する。同期中は確認が出る |

警告は通知されません。メインの窓の左の欄の上と、アイコンの表示の「（警告あり）」だけで知らせます。

### 端末

| 表示 | 内容 |
|---|---|
| 端末の名前 | ペアリング時に端末が申告した表示名 |
| 状態 | 接続中、未接続 |
| 前回の同期 | 日時、結果（完了、一部失敗、中断、失敗）、件数（追加、更新、削除）。容量不足で始められなかった同期は「失敗」と表示されます（端末の画面には「未開始」と出ます） |
| 失敗の種類 | 失敗があれば、その名前と件数 |

- 端末は 1 台だけです。
- 「ペアリングを解除する」を押すと、確認は出ず、すぐに解除されます。
- 曲名や曲ごとの一覧は PC に送られません。除外された曲の一覧は、端末の結果の画面で見ます。
- 端末が登録されていないときは「ペアリングした端末はありません」と表示されます。ペアリングは窓の「ペアリング」の「コードを表示」から始めます。

### 警告

メインの窓の左の欄の上に、次の警告が出ます。表の左の列は、画面に出る文です。

| 警告 | 条件 | 対処 |
|---|---|---|
| XML がしばらく更新されていません | 更新日時が設定ファイルの日数（`stale_days`）より古い（iTunes ライブラリの欄には日数も出る） | iTunes の XML の共有が有効か確かめる。iTunes を起動してライブラリを変える |
| ポートが使用中のため、サーバーを起動できません | 設定のポートを開けず、サーバーが止まっている | 設定ファイル（`settings.json`）の `port` で別のポートにする。変えた後は、PC と端末の両方で解除してから再ペアリングする |
| サーバーを起動できません。ログを確かめてください | ポートの使用中と鍵の保管の失敗以外の理由で、サーバーが起動していない | 窓の「ログの場所を開く」でログを開いて原因を確かめる。ポートの値が不正なら、`settings.json` の `port` を直す |
| 鍵を読み出せません。対処はマニュアルを見てください | 鍵を読み出せず、サーバーが起動していない（トレイの表示にも出る） | 下の「困ったとき」の「鍵の保管に失敗」のとおりに直し、再ペアリングする |
| 端末の鍵が見つかりません。… | この端末の鍵が見つからない | PC の「端末」と端末の設定の両方でペアリングを解除してから、再ペアリングする |
| 証明書を作り直しました。端末でもう一度ペアリングしてください | PC の鍵を作り直し、ペアリング済みの端末がある。再ペアリングを済ませると消える | PC の「端末」と端末の設定の両方で解除してから、再ペアリングする |
| 設定を読めなかったため、元のファイルを退避して初期設定で起動しました | `settings.json` を読めなかった。元のファイルは `settings.json.bad` に退避された | 窓の「設定」で XML の場所などを確かめる。ペアリングした端末の登録は初期設定で空になるので、端末を使うときは再ペアリングする |

- 「XML を読めません」は、この警告の一覧には出ません。iTunes ライブラリの欄に赤字で出ます。窓の「設定」で XML の場所を確かめ、iTunes の XML の共有を有効にしてください。

## 設定

メインの窓の左の欄の「設定」には次の項目だけがあります。古いと警告する日数とサーバーのポートは、画面からは変えません（2026-11-07）。設定ファイル `%APPDATA%\playlist-sync-fox\settings.json` の `stale_days`（0 で警告しない）と `port`（既定は 47800。1024〜65535 の値にしてください。値の範囲は検査されず、開けない値にすると「サーバーを起動できません」の警告が出ます。変えると、PC と端末の両方で解除してから再ペアリングが要る）を、PC のアプリを終了してから書き換えます。

| 項目 | 内容 |
|---|---|
| XML の場所 | iTunes ライブラリ XML のパス。未設定のときは、実際に読んでいる既定のパスが欄に入っています。「確認して保存する」で検査し、読めれば「保存しました」、読めなければ「この場所の XML を読めません」と出て保存されません |
| Windows へのログイン時に起動する | チェックを切り替えるとすぐ保存されます。既定は有効 |
| ライセンス | ボタン。使っているオープンソースのライセンスの一覧（名前、版、ライセンスの種類）と、各ライセンスの全文を開きます。部品が NOTICE を持つときは、全文と一緒に出ます。同梱している Java 実行環境は、実行環境が持つモジュールごとの全文が出ます |

ログのフォルダは設定の項目にありません。窓の下のログの欄の「ログの場所を開く」か、トレイの「ログの場所を開く」で開きます。

## 困ったとき

| 症状・表示 | 原因と対処 |
|---|---|
| PC に届かない | 端末と PC が同じネットワークか確認します。PC のアプリが起動しているか（トレイにあるか）確認します。Tailscale では、入力した MagicDNS 名が、Tailscale のアプリで見える PC の名前と合っているか確認します。ポートが使用中なら警告が出るので、設定で別のポートにします |
| 自動の同期が始まらない | 次のいずれかです。(1) 周期（6 時間）がまだ来ていない。(2) 手動の同期が完了または一部失敗で終わった後の 30 分間（失敗した手動の同期の後は止まりません）。(3) 前回の同期で鍵が合わず（証明書が変わった場合を含み、時計のずれは含まない）、再ペアリングまで止まっている。(4) 前回が容量不足で、手動の同期が成功するまで止まっている。(5) PC の曲とプレイリストを最後に取得できた同期が完了で、PC の曲とプレイリストがそれと同じため、取得せずに終わった。(6) モバイル回線の Tailscale では起動しない。外出先では手動で同期してください |
| 端末と PC の時計が違う | 時計のずれが数分以上あると、署名が通りません。端末の時刻が PC の起動時刻より前のときも、ずれが小さくても通りません。端末か PC の時計を合わせてください |
| ペアリングのやり直しが必要 | 鍵が合っていません。PC の窓の「端末」で「ペアリングを解除する」を押し、端末の設定でも解除してから、再ペアリングします |
| サーバーを起動できません | 鍵の保管の失敗以外の理由で、サーバーが起動していません。トレイの表示は、ポートの使用中のときも同じです。メインの窓の警告は、ポートの使用中なら「ポートが使用中のため、サーバーを起動できません」、それ以外なら「サーバーを起動できません。ログを確かめてください」です。原因はログに残ります。窓の「ログの場所を開く」でログを開き、「server」か「secrets」の行を確かめます。ポートの値が不正なときは、設定ファイルの `port` を直します |
| 鍵の保管に失敗 | 鍵を読み出せないため、サーバーが起動していません。原因の例は、別の Windows ユーザーで起動した、`secrets.bin` を別の PC や別の利用者から移した、ファイルが壊れた、です。(1) 元の Windows ユーザーでサインインして、アプリを起動し直します。(2) 直らなければ、アプリを終了し、`secrets.bin`（場所は「データの置き場と削除」）を別名に変えて退避してから起動します。新しい鍵が作られ、端末のペアリングはすべて無効になります。(3) PC の「ペアリングを解除する」と端末の設定の両方で解除してから、再ペアリングします |
| 容量不足 | 端末の空きが足りません。不足分が端末に表示されます。端末の空きを作ってください |
| PC の XML が読めない | iTunes の「iTunes ライブラリ XML をほかのアプリケーションと共有」（英語版では「Share iTunes Library XML with other applications」）の項目が有効か確認します。窓の「設定」で XML の場所を確認します。PC を再起動した直後にも出ます。その場合は、もう一度同期します |
| ファイルが無い | iCloud から未ダウンロードの曲などです。端末の結果の一覧で確認します |
| 途中で切れた | 再度同期します。続きから転送されます |
| 時間の上限 | Android 15 以降の 1 日の上限です。次回の同期で続きます |
| 曲が変わった | 同期の途中で PC の曲が変わりました。再度同期します |
| 保存に失敗 | 端末側の保存に失敗しました。端末の空きと、結果の一覧を確認します |
| 保護付き（.m4p）の曲 | 転送されません |

ログに鍵とコードは出ません。ログに出る曲の情報は、曲の表示名（ファイル名から拡張子を除いたもの）と大きさだけで、曲のパスは出ません。

## データの置き場と削除

| 内容 | 場所 |
|---|---|
| 設定 | `%APPDATA%\playlist-sync-fox\settings.json` |
| ログ | `%LOCALAPPDATA%\playlist-sync-fox\logs\` |
| 鍵 | 設定と同じフォルダの `secrets.bin`（Windows の DPAPI で暗号化） |
| 証明書 | 設定と同じフォルダの `tls-cert.pem`（公開してよい証明書。秘密鍵は `secrets.bin` にある） |
| 二重起動の防止 | 設定と同じフォルダの `app.lock`（起動中のアプリが開いたままにするロック用のファイル）。2 つ目の起動は、同じフォルダに `open-window.signal`（窓を開く印）を置いて終わり、1 つ目が見つけて窓を開くと消えます |

- 設定が壊れたときは、`settings.json.bad` に退避され、既定の設定で起動します。ペアリングの鍵は残ります。
- 通信は PC の自己署名の証明書で暗号化されます。鍵のない要求には、LAN の中でも配信しません。

### アンインストール

1. 窓の「設定」で「Windows へのログイン時に起動する」を外します。
2. トレイのメニューの「終了」でアプリを終了します。
3. インストーラーで入れたときは、Windows の「設定」→「アプリ」→「インストールされているアプリ」から KudagiTune をアンインストールします。zip で入れたときは、展開したフォルダを削除します。
4. 上の表の設定とログのフォルダを削除します。鍵もここにあります。アンインストールでは、これらは消えません。
5. 端末側でも、必要なら端末のアプリでペアリングを解除します。
