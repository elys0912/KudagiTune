# playlist-sync-fox 説明書（PC 版）

対象の版：設計の第 5 稿（2026-11-06）に、2026-11-07 の先生の決定（プレイリストの選択を端末へ、PC の画面を最小に、用語「確認コード」）を反映したもの
この説明書は設計を元に書いた。実機での確認は未。

## できること

- PC の iTunes のプレイリストを、Android 端末へ同期します。
- PC のアプリはサーバーとして動きます。端末が PC に取りに行きます。
- PC のアプリはトレイに常駐します。曲の変換や iTunes への書き戻しはしません。
- 同期の開始は端末の操作です。手動の同期と、従量制でないネットワークにつながっている間に端末が周期で起動する自動の同期があります。

## 動作環境

| 項目 | 内容 |
|---|---|
| OS | Windows 11 を前提とします。Windows 10 は未確認です |
| iTunes | iTunes 12.x（Windows 版）。Apple Music アプリは未対応です |
| ネットワーク | 同一 LAN、Tailscale、USB テザリングのいずれか |

## 導入

1. GitHub の Releases から PC 版の zip をダウンロードします。更新の確認はアプリ内でしません。新しい版は Releases で確認してください。
2. 好きなフォルダに zip を展開します。JVM が同梱されているため、Java の導入は要りません。
3. 展開したフォルダの実行ファイルを起動します。
4. コード署名をしていないため、SmartScreen の警告が出ます。内容を確認したうえで「詳細情報」から実行します。
5. 起動すると、画面は開かずトレイに入ります。初回だけ、ペアリングの画面が自動で開きます。

「ログイン時に起動」は既定で有効です。端末の自動の同期は、PC のアプリが動いていることが前提です。

## iTunes の設定

PC のアプリは、iTunes が出力する XML（iTunes Music Library.xml）を読みます。

1. iTunes の「編集」→「環境設定」→「詳細」を開きます。
2. 「Share iTunes Library XML with other applications」に当たる項目を有効にします。日本語版での項目名は未確認です。
3. 設定の窓の「XML の場所」を確認します。未設定のときは、`%USERPROFILE%\Music\iTunes\iTunes Music Library.xml` を試します。iTunes 12.13.7.1 ではこの場所でした。ほかの版では違う場合があるので、読めないときは手で指定してください。
4. 指定した場所が読めるか、その場で検査されます。読めなければ結果が横に表示され、保存されません。

iTunes を起動してライブラリを変えると、XML が更新されます。

## プレイリストの選択

同期するプレイリストは、PC ではなく端末のアプリで選びます（端末の説明書の「プレイリストの選択」）。PC の画面にはプレイリストの一覧もチェックボックスもありません。

- PC は、端末が選んだプレイリストの曲だけを配ります。選んでいない曲は配りません。
- PC の設定ファイルには選択を保存しません。古い版の設定ファイルに選択が残っていても、読み捨てます。
- PC の画面に出るのは、ペアリング、状態、XML の場所、ログイン時の起動、ライセンスだけです。

## ペアリング

初回だけ、PC と端末を結び付けます。

1. トレイのメニューの「ペアリングコードを表示」を選びます。ペアリングの画面が開きます。
2. 端末のアプリでペアリングを始めます。
3. PC の画面に出た 6 桁の「ペアリングコード」を、端末に入力します。ペアリングコードは通信には流れません。
4. 両方の画面に「確認コード」が出ます。同じかどうか見比べてください。確認コードは PC の公開鍵のハッシュです。端末には、コードを送って PC から応答が返った時点で出ます。端末への保存は、ペアリングが成功した時点で確定します。違うと思うときは、メインの窓の「ペアリングを解除」と端末の設定の両方で解除してから、再ペアリングしてください。

ペアリングコードには有効期限があります。期限が切れた後、または使った後は無効になり、新しいコードは操作するまで出ません。「無効にして作り直す」で作り直せます。失敗が上限を超えると、そのコードは無効になり、しばらく作り直せません。窓を閉じても、コードは無効になります。

### 接続先

ペアリングの画面には、端末が接続する先が表示されます。

| 接続方法 | 手順 |
|---|---|
| 同一 LAN | 端末が自動で PC を見つけます。見つからないときは、画面の「接続先の一覧」の IP とポート（例：192.0.2.10:47800）を端末に手入力します |
| Tailscale | PC の MagicDNS 名を端末に手入力します。名前は PC の画面に表示され、コピーできます。名前を取得できない場合は行が出ません（実機で未確認）。そのときは、Tailscale の管理画面で調べた名前を端末に入力します |
| USB テザリング | 端末のテザリングを有効にします。端末が PC を見つけられなければ、画面に別行で出るテザリング側の IP を端末に手入力します |

### 端末を入れ直したとき

端末のアプリを入れ直すと、古いペアリングが PC に残ります。

1. メインの窓の「端末と最後の同期」で「ペアリングを解除」を押し、確認します。
2. もう一度、上の手順でペアリングします。

端末側で解除する場合は、端末の操作で行います。

## 画面の見方

### トレイ

トレイのアイコンの左クリックで、メインの窓が開きます。メニューには次の項目があります。

| 項目 | 動作 |
|---|---|
| 状態の表示 | 「待機中」「同期中」「XML が読めない」「ペアリング未済」「鍵の保管に失敗」のどれかです。同期の件数は出ません。進み具合は端末で見てください。「鍵の保管に失敗」のときは、鍵を読み出せないためサーバーが起動していません |
| 開く | メインの窓を開く |
| ペアリングコードを表示 | ペアリングの画面を開く |
| 設定 | 設定の窓を開く |
| ログの場所を開く | ログのフォルダをエクスプローラで開く |
| 終了 | サーバーを止めて終了する。同期中は確認が出る |

警告があるときは、アイコンに印が付きます。警告は通知されません。メインの窓の帯と、アイコンの印だけで知らせます。

### 端末と最後の同期

| 表示 | 内容 |
|---|---|
| 端末の名前 | ペアリング時に端末が申告した表示名 |
| 状態 | 接続中、未接続 |
| 最後の同期 | 日時、結果（完了、一部失敗、中断、失敗）、件数（足した、置き換えた、消した、除外した）。容量不足で始められなかった同期は「失敗」と表示されます（端末の画面には「未開始」と出ます） |
| 失敗の種類 | 失敗があれば、その名前 |

- 端末は 1 台だけです。
- 曲名や曲ごとの一覧は PC に送られません。除外された曲の一覧は、端末の結果の画面で見ます。
- 端末が登録されていないときは「端末がありません」と表示され、ペアリングのボタンが出ます。

### 警告

| 警告 | 条件 | 対処 |
|---|---|---|
| XML が読めない | XML が無い、または読めない | 設定の窓で XML の場所を確かめる。iTunes の XML の共有を有効にする |
| XML が古い | 更新日時が設定ファイルの日数（`stale_days`）より古い | iTunes の XML の共有が有効か確かめる。iTunes を起動してライブラリを変える |
| 鍵が見つからない | この端末の鍵が見つからない | PC の「端末と最後の同期」と端末の設定の両方でペアリングを解除してから、再ペアリングする |
| 鍵の保管に失敗 | 鍵を読み出せず、サーバーが起動していない（メインの窓の帯とトレイの状態に出る） | 下の「困ったとき」の「鍵の保管に失敗」のとおりに直し、再ペアリングする |
| ポートが使用中 | 設定のポートを開けず、サーバーが止まっている | 設定ファイル（`settings.json`）の `port` で別のポートにする。変えた後は、PC と端末の両方で解除してから再ペアリングする |
| 証明書が変わった | PC の鍵を作り直した | PC の「端末と最後の同期」と端末の設定の両方で解除してから、再ペアリングする |

## 設定

設定の窓には次の項目だけがあります。変更は項目ごとに検査され、すぐ保存されます。保存ボタンはありません。古いと警告する日数とサーバーのポートは、画面からは変えません（2026-11-07）。設定ファイル `%APPDATA%\playlist-sync-fox\settings.json` の `stale_days`（0 で警告しない）と `port`（1024〜65535。変えると、PC と端末の両方で解除してから再ペアリングが要る）を、PC のアプリを終了してから書き換えます。

| 項目 | 内容 |
|---|---|
| XML の場所 | iTunes ライブラリ XML のパス。読めなければ保存されません |
| ログイン時に起動 | 既定は有効 |
| ログのフォルダ | 表示のみ |
| ライセンス | ボタン。使っているオープンソースのライセンスの一覧を開きます |

## 困ったとき

| 症状・表示 | 原因と対処 |
|---|---|
| PC に届かない | 端末と PC が同じネットワークか確認します。PC のアプリが起動しているか（トレイにあるか）確認します。Tailscale では、入力した MagicDNS 名が合っているか確認します。ポートが使用中なら警告が出るので、設定で別のポートにします |
| 自動の同期が始まらない | 次のいずれかです。(1) 周期（6 時間）がまだ来ていない。(2) 手動の同期が完了または一部失敗で終わった後の 30 分間（失敗した手動の同期の後は止まりません）。(3) 前回の同期で鍵が合わず（証明書が変わった場合を含み、時計のずれは含まない）、再ペアリングまで止まっている。(4) 前回が容量不足で、手動の同期が成功するまで止まっている。(5) PC の曲とプレイリストを最後に取得できた同期が完了で、PC の曲とプレイリストがそれと同じため、取得せずに終わった。(6) モバイル回線の Tailscale では起動しない。外出先では手動で同期してください |
| 端末と PC の時計が違う | 時計のずれが数分以上あると、署名が通りません。端末の時刻が PC の起動時刻より前のときも、ずれが小さくても通りません。端末か PC の時計を合わせてください |
| ペアリングし直しが要る | 鍵が合っていません。PC で「ペアリングを解除」し、端末の設定でも解除してから、再ペアリングします |
| 鍵の保管に失敗 | 鍵を読み出せないため、サーバーが起動していません。原因の例は、別の Windows ユーザーで起動した、`secrets.bin` を別の PC や別の利用者から移した、ファイルが壊れた、です。(1) 元の Windows ユーザーでサインインして、アプリを起動し直します。(2) 直らなければ、アプリを終了し、`secrets.bin`（場所は「データの置き場と削除」）を別名に変えて退避してから起動します。新しい鍵が作られ、端末のペアリングはすべて無効になります。(3) PC の「ペアリングを解除」と端末の設定の両方で解除してから、再ペアリングします |
| 容量不足 | 端末の空きが足りません。不足分が端末に表示されます。端末の空きを作ってください |
| PC の XML が読めない | iTunes の「Share iTunes Library XML with other applications」に当たる項目（日本語名は未確認）が有効か確認します。設定の窓で XML の場所を確認します。PC を再起動した直後にも出ます。その場合は、もう一度同期します |
| ファイルが無い | iCloud から未ダウンロードの曲などです。端末の結果の一覧で確認します |
| 途中で切れた | 再度同期します。続きから転送されます |
| 時間の上限 | Android 15 以降の 1 日の上限です。次回の同期で続きます |
| 曲が変わった | 同期の途中で PC の曲が変わりました。再度同期します |
| 保存に失敗 | 端末側の保存に失敗しました。端末の空きと、結果の一覧を確認します |
| 保護付き（.m4p）の曲 | 転送されません |

ログに鍵とコードは出ません。曲のパスは PC のログにだけ出ます。

## データの置き場と削除

| 内容 | 場所 |
|---|---|
| 設定 | `%APPDATA%\playlist-sync-fox\settings.json` |
| ログ | `%LOCALAPPDATA%\playlist-sync-fox\logs\` |
| 鍵 | 設定と同じフォルダの `secrets.bin`（Windows の DPAPI で暗号化） |
| 証明書 | 設定と同じフォルダの `tls-cert.pem`（公開してよい証明書。秘密鍵は `secrets.bin` にある） |

- 設定が壊れたときは、`settings.json.bad` に退避され、既定の設定で起動します。ペアリングの鍵は残ります。
- 通信は PC の自己署名の証明書で暗号化されます。鍵のない要求には、LAN の中でも配信しません。

### アンインストール

1. トレイのメニューの「終了」でアプリを終了します。
2. 展開したフォルダを削除します。
3. 上の表の設定とログのフォルダを削除します。鍵もここにあります。
4. 端末側でも、必要なら端末のアプリでペアリングを解除します。

インストーラーは使っていないため、レジストリの登録はアプリが行う「ログイン時に起動」だけです。削除前に設定の窓で無効にしておくと確実です（実機で未確認）。
