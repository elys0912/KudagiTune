### B4-5 PC の画面 W1〜W5（F5、F6-5）

PC のアプリはトレイに常駐し、画面は 1 枚の窓（メインの窓）とする（F5-1。設定は窓の左の欄の W5。Q16-3）。窓の上は OS のタイトルバーを使い、独自の帯は持たない（Q16-6）。書体は OS の既定で、同梱しない（等幅も OS の既定。B1-9 の 19、Q14、Q16-5）。画面に置くのはペアリング、状態の表示、XML の場所の指定だけで、ほかに必要な設定としてライセンスの表示とログイン時起動の切り替えを残す（D17。2026-11-07）。画面は Compose Multiplatform（D4）。言語は日本語のみ（F6-5、暫定）。文言は 1 か所の文字列の表にまとめ、後から言語を足せる形にする（決定（未付番）。根拠：F6-5 が「暫定」のため）。

#### W1 トレイのメニュー

メニューに状態の行は置かない。状態は、アイコンにマウスを合わせたときのツールチップの文字で出す（review-15。X5-5）。ツールチップは製品名を前に付け、「KudagiTune：待機中」の形にする。状態は次のいずれか 1 つで、優先順は表の上から（表の「ツールチップ」の列は、「KudagiTune：」に続く部分）。

| 状態 | ツールチップ | 条件 |
|---|---|---|
| 鍵の保管に失敗 | 「鍵の保管に失敗しました」 | 鍵の保管の復号に失敗してサーバーを起動できない（X5-2）。対処は説明書（J44） |
| サーバーを起動できない | 「サーバーを起動できません」 | 鍵の保管の失敗以外の起動の失敗（ポートの使用中、鍵と証明書の用意の失敗、そのほか。X5-5。2026-11-09）。ポートの使用中もこの表示にする |
| ペアリング未済 | 「ペアリングしていません」 | 端末が無い |
| XML が読めない | 「XML を読めません」 | W2 の XML 欄が「読めない」 |
| 同期中 | 「同期中」 | 同期の進行がある（P2 の送信中、またはその直近。P1 だけでは同期中としない） |
| 待機中 | 「待機中」 | 上のいずれでもない（XML が未確認の間も） |

- 同期の進行は端末の通知が正で、PC は全体の曲数を知らないため、トレイの表示に件数を出さない（件数と割合は窓の「同期の進行状況」。D22）
- 警告（W2 の警告の一覧）が 1 件でもあれば、ツールチップの末尾に「（警告あり）」を付ける（例：「KudagiTune：待機中（警告あり）」）。アイコンの絵は変えない

| 項目 | 動作 |
|---|---|
| 開く | メインの窓を開く（アイコンの左クリックも同じ） |
| ペアリングコードを表示 | W4 を開く。ペアリング済み（端末がある）の間は押せない（review-15。X5-3） |
| 設定 | メインの窓を開く（「開く」と同じ。窓は 1 枚で、設定は窓の左の欄の W5。Q16-3） |
| ログの場所を開く | B4-6 のログのフォルダをエクスプローラで開く |
| 終了 | サーバーを止めて終了。同期中は確認を出す |

- 起動時の窓（review-15。X5-6）：手動の起動（`--background` なし）はメインの窓を開く。`--background`（ログイン時の起動）はトレイだけに入る。ただし初回（ペアリング未済の初回の印）は、`--background` でも窓を開く。W4 のペアリングコードは自動では出さない（決定（未付番）。根拠：初回に何をするかを探させないため。コードは利用者の操作で出す）
- 二重起動を防ぐ（X5-6。`app.lock`）。2 つ目の起動は、1 つ目のメインの窓を開いて終わる
- OS ログイン時の自動起動は、W5 の項目「ログイン時に起動」で選べる。既定は有効（決定（未付番）。根拠：端末の自動起動（D13）は PC のサーバーが動いていることが前提）

#### W2 状態の警告（F5-6、F1-8。2026-11-07 に「プレイリストの選択」から改めた）

- プレイリストの選択は端末の S6 へ移した（F3-11、D15）。PC の画面にプレイリストの一覧、チェックボックス、選択の保存は無い。`settings.json` に選択を持たない（古い設定に `selected_playlist_ids` が残っていても読み捨てる）
- 警告の一覧（左の欄の上段。メインの窓）：下表の 7 種。警告は状態の表示で、操作は伴わない。通知しない（トレイのツールチップの「（警告あり）」と一覧だけ。W1）
- XML の状態は、警告の一覧とは別に、iTunes ライブラリの欄（XML 欄）に出す（review-15。X5-5）。「読めない」（読み直しの上限（V6）を超えても読めない、または XML が無い）は警告の一覧に入れず、XML 欄の赤字だけで出す。文には、iTunes の詳細設定で XML の共有を有効にする案内を含め、設定名は日本語名「iTunes ライブラリ XML をほかのアプリケーションと共有」と英語名「Share iTunes Library XML with other applications」の両方を並べる（Q16-4。日本語名は実物で未確認で、確認待ちの T11 で確かめる）。端末は E4 で止まる（B2-3）。「未確認」（起動直後と、読めずに読み直している間）は「XML を確かめています」を成功の色（緑）でなく薄い文字で出す。「古い」は警告の一覧と XML 欄の両方に出す

| 警告 | 条件 | 文言の要点 | E |
|---|---|---|---|
| XML が古い | XML の更新日時が基準日数（V5）より古い | 「XML がしばらく更新されていません」。日数は XML 欄に出す | — |
| ポートが使用中 | 起動時に設定のポートを開けない。サーバーは止まった状態で続行する（X5-6） | 「ポートが使用中のため、サーバーを起動できません」 | — |
| サーバーを起動できない | 鍵と証明書の用意の失敗、ポートの使用中以外の起動の失敗（X5-5。2026-11-09）。ポートの範囲の検査は足さず、範囲外の値はこの警告になる | 「サーバーを起動できません。ログを確かめてください」 | — |
| 鍵の保管に失敗 | 鍵の保管（`secrets.bin`）の復号に失敗し、サーバーを起動できない（X5-2。W1 のツールチップにも出す。J44） | 「鍵を読み出せません。対処はマニュアルを見てください」 | — |
| 鍵が無い | 端末の署名用の鍵（K1）を `secrets.bin` から読めない。署名の要求は 401 と同じ扱いで拒否する（W3 にも出す） | 「端末の鍵が見つかりません。PC と端末の両方で解除してから、もう一度ペアリングしてください」 | — |
| 証明書を作り直した | 鍵を新しく作り（X5-2）、ペアリング済みの端末があり、再ペアリングがまだ済んでいない。再ペアリングが済んだら消える | 「証明書を作り直しました。端末でもう一度ペアリングしてください」 | — |
| 設定を読めなかった | `settings.json` を読めず、退避して初期設定で起動した（B4-6） | 「設定を読めなかったため、元のファイルを退避して初期設定で起動しました」 | — |

- 「選択が空」の警告は廃止した（PC は選択を持たない）。端末は選択が空なら同期を始めない（F3-11）

#### W3 端末と最後の同期（F5-3、D11）

- 表示項目：端末の名前（ペアリング時に端末が申告する表示名）、状態（接続中／未接続）、最後の同期の日時、結果（完了、一部失敗、中断、失敗の 4 値。P4 の `outcome`。端末の「未開始」は失敗に畳まれて届く。語は X3-5 の表）、結果の件数（B2-8 の報告の項目：足した、置き換えた、消した、除外した）、失敗の種類（E の名前と件数で表示する。E の番号は出さない。F6-2。review-15。X5-5）
- 最後の同期の情報は、P4（結果の報告。B2-8 の報告の項目。要約のみ）で端末から受けた内容を保存したもの。曲名や曲ごとの一覧は PC へ送らない（N1-6）。除外の曲の一覧は端末の画面にだけある
- 「接続中」は、直近 1 回の要求から経過した時間（V33）以内の署名つき要求があることで判定する
- 端末は 1 台（D11）。保存の形は端末の識別子（乱数 16 バイト。UUID の形で表す）をキーにした表で持ち、画面は 1 行だけ表示する。ペアリング未済は「端末がありません。ペアリングする」のボタンを出す
- 操作：「ペアリングを解除する」（F2-7）。確認を出さず（Q16-1）、K1 と端末の登録を消す。端末側の解除は端末で行う。端末を入れ直したときは新しい識別子になり、既存のペアリングが残るため、ここで解除してから W4 でペアリングし直す（D14）

#### W4 ペアリング（F5-4、F2-3、F2-5）

| 項目 | 内容 |
|---|---|
| ペアリングコード | 6 桁の数字（利用者が端末へ入力する。確認コードとは別）を大きく表示。有効期限までの残り時間と「無効にして作り直す」ボタン。使用後と V3 に達したときは自動で無効にし、新しいコードは利用者の操作があるまで出さない |
| 試行の失敗 | 失敗回数が上限（V2）に達したら、そのコードを無効にして帯で知らせる（N1-3）。回数は P6 の不一致で数える（B4a の B4-2） |
| MagicDNS 名 | 行を置かない。PC は自分の MagicDNS 名を取得しない（Q13。2026-11-09 先生の決定）。利用者が Tailscale のアプリで PC の名前を見て、端末に入力する（説明書）。端末の手入力の形式は B4a の B4-1 |
| 接続先の一覧 | LAN の IP とポート（例：192.0.2.10:47800 の形。ポートは V16 の既定）。USB テザリング時の IP は、テザリングのアダプターの IP を別行で表示 |
| 確認コード | K2 の公開鍵（SPKI）のハッシュ（画面では「確認コード」。旧称「指紋」。D18）を、グループ分けした 16 進で表示し、コピーのボタンを付ける（画面に出ている文字列をクリップボードへ写す。review-15。X5-8）。端末の画面に出る確認コードとの見比べ用（表示だけ。端末の保存は P6 の成功で確定し、違うと思えば PC の W3 と端末の S5 の両方で解除する。J27。Q5、B4a の B4-2） |

- 端末がある（ペアリング済みの）間は、W4 の「コードを表示」を押せず（W1 の「ペアリングコードを表示」も同じ）、TXT の `pair=1` も広告しない（端末は 1 台。X5-3。review-15）
- 端末を入れ直したときは、W3 で解除してからペアリングする旨を、W4 に注として出す（端末の S2 にも同じ案内、B3 へ依頼）
- コードと鍵の値は、画面にだけ出す。ログとクリップボードへの自動コピーはしない（N1-6）。コピーのボタンは確認コードに付ける（MagicDNS 名の行は置かない。Q13）
- 窓を閉じるとコードを無効にする（決定（未付番）。根拠：画面に出ていないコードを残さない）

#### W5 設定（F5-5、F1-8）

| 項目 | 既定 | 備考 |
|---|---|---|
| XML の場所 | `%USERPROFILE%\Music\iTunes\iTunes Music Library.xml`（iTunes 12.x の既定。iTunes 12.13.7.1 と Windows 11 で確認済み（2026-11-06 の実物の確認）。ほかの版と OS による差は未確認） | 「参照」ボタンで変更。未設定のときは既定のパスを欄に出す（X5-9）。変更時に読めるかを確かめ、結果を横に表示（E4 の判定と同じ） |
| 古いと警告する日数 | V5 | 画面からは変えない（`settings.json` の `stale_days`。0 で警告しない。2026-11-07 に画面から外した。D17） |
| ログイン時に起動 | 有効 | W1 の注 |
| サーバーのポート | V16 で固定 | 画面からは変えない（`settings.json` の `port`。2026-11-07 に画面から外した。D17）。使用中なら起動時に警告し、利用者が設定ファイルで変える。自動では変えない（端末が保存した Tailscale と USB の宛先のポートが外れ、自動起動が届かなくなるため。決定（未付番））。ポートを変えたときは、PC の W3 と端末の S5 の両方で解除してから、再ペアリングする（再ペアリングで宛先を保存し直す。新しい仕組みは足さない）。変更後は、広告と W4 の表示が更新される（B4a の B4-1） |
| ライセンス | ボタン（設定を持たない表示のみの項目） | 使う OSS のライセンスの一覧を開く（B4-7） |

- ポートが使用中のときの警告は、トレイのツールチップの「（警告あり）」と W2 の警告の一覧に出す（W1 と同じ条件）
- W5 の項目は、XML の場所、ログイン時に起動、ライセンスだけ（D17）。ログのフォルダの表示項目は置かない。窓のログの欄の「ログの場所を開く」とトレイの同名の項目で足りる（Q16-2）
- 設定の保存と読み込みは B4-6 の形式に従う。W5 に「保存」ボタンは置かず、項目ごとに即保存する

### B4-6 設定とログの置き場（F6-1、F6-3、N1-4、N1-6）

#### PC（desktop）

| 種別 | 置き場 | 内容 |
|---|---|---|
| 設定 | `%APPDATA%\playlist-sync-fox\settings.json` | `pc_id`、XML の場所、日数、ポート、ログイン時起動、`library_id` の代わりの乱数（XML に無いときだけ）、ペアリング済みの端末の表（識別子、表示名、登録日時、最後の同期の要約） |
| ログ | `%LOCALAPPDATA%\playlist-sync-fox\logs\` | 動作のログ。ファイルは日ごとではなく、大きさで切り替える |
| 鍵 | `%APPDATA%\playlist-sync-fox\secrets.bin`（DPAPI で暗号化したファイル）。K1 と K2 の秘密鍵を入れる（B4a の B4-3）（review-05 の基本設計の直し 2） | 設定のファイル（`settings.json`）には置かない（N1-4） |
| 証明書 | `%APPDATA%\playlist-sync-fox\tls-cert.pem`（K2 の証明書） | 公開してよい。秘密鍵は `secrets.bin` |

- 場所の規則：利用者のユーザー領域だけに書く。インストール先（Program Files など）には書かない（F6-3。決定（未付番）。根拠：管理者権限なしで動かすため）
- 設定の書き込みは、一時ファイルへ書いてから置き換える（途中で壊れたファイルを残さない）。読めない設定は `settings.json.bad` に退避し、既定で起動して警告を出す（決定（未付番）。根拠：W2 と同じく、読めないときに黙って初期化しない）
- 設定の形式は kotlinx.serialization の JSON（B1 の技術の選定）。先頭に `schema_version` を持ち、版の上げ方は詳細設計
- ペアリング済みの端末の表は、D11 のため端末の識別子をキーにした配列で持つ。最初の版は要素が 1 つまで

#### library_id の代わりの値の保存（B2-4）

- `library_id` は XML の `Library Persistent ID` を使う。XML に無いときだけ、代わりの乱数（128 ビット。生成は暗号用の乱数の部品、B4a の B4-2 の置き場に従う）を初回に作り、`settings.json` に保存する
- 設定を消され、代わりの乱数を使っていたときは新しい値になる。端末は新しい `library_id` を見て、以前の PC と別物として扱い、「消す」を確認なしに進めない（Q9。最初の版は 1 台の PC。マニフェストの扱いは B2）
- `library_id` は秘密ではないが、鍵とは別の値とし、署名の鍵の導出に使わない

#### ログ（F6-1）

- 書く項目：時刻、レベル、モジュール、メッセージ、E の番号（あれば）。PC と端末で同じ項目とする。PC のログにはファイルのパスを出してよい（N1-6）。曲名は出してよい。鍵、コード、署名の値、nonce、証明書の秘密鍵、要求の署名ヘッダは出さない
- 上限と入れ替え：PC は V8（1 ファイル 5 MB を 3 世代）。上限を超えたら新しいファイルへ切り替え、世代数を超えた古いものを消す（F6-1）
- 外へ送らない（F6-1）。「ログの場所を開く」（W1）で利用者が自分で扱う
- レベルは 3 段（情報、警告、エラー）。詳細ログは最初の版では持たない（決定（未付番）。根拠：値の出し過ぎの防止と実装の最小化）

#### 端末（android）

| 種別 | 置き場 | 内容 |

#### Android：APK の署名と鍵の置き場（N4-2）

- APK は release ビルドを自分の署名の鍵（keystore）で署名する。同じ鍵で署名した APK でないと更新（上書き）できないため、鍵を失うと更新できない
- 鍵の置き場：先生の手元の暗号化した保管先に置き、repo に入れない。CI に置く場合は、Secrets に登録した鍵を環境変数で渡す形に限り、ログに出さない（未確認：CI の機能の細部は B1 のビルド・CI の方針に合わせる）
- 鍵のバックアップを別の場所に 1 つ持つ（決定（未付番）。根拠：失うと更新できない）
- Play ストアへ移る場合は、Play 側の署名の仕組みを使う（将来、D12。未確認）。その時の鍵の扱いは別に決める

#### 下書き Release の流れ（B1 の依頼）

| 段階 | 内容 | 担当 |
|---|---|---|
| 1 | 版のタグを打つ（形式は B1-6 のとおり） | 手動 |
| 2 | CI がタグを契機に、PC の zip と APK を作る。APK は署名の鍵が CI にあるときだけ署名する | CI |
| 3 | CI が「下書き」の Release を作り、配布物とチェックサム（SHA-256 の一覧）を付ける | CI |
| 4 | 手元で APK を実機に入れ、B4-8 の確認の表（C-1〜C-17）の該当項目を確かめる | 手動 |
| 5 | 下書きを公開する。公開の前に、repo が public であることを確かめる（D12） | 手動 |

- 公開の操作は手動のままにする（決定（未付番）。根拠：実機の確認の後に公開するため、CI からは公開しない）
- Release の本文には、変更の要点、PC の導入手順、APK の「提供元不明のアプリ」の許可の手順を書く（F6-4：更新の確認は持たないので、案内は Release の本文が担う）
- チェックサムは配布物の取り違えの確認用。署名の代わりではない

#### OSS ライセンスの表示（N4-4）

- 使う OSS（Kotlin、Ktor、Room、Compose、JmDNS か代替など。名前は B1 の技術の選定に従う）のライセンスの一覧を、ビルド時に生成して配布物に同梱する（Gradle のプラグイン Licensee（`app.cash.licensee`）を使う。`artifacts.json` を出力し Android のアセットへ同梱できる。facts-jvm 8b。JSON の項目の一覧は未確認）
- 表示の場所：PC は W5 の「ライセンス」ボタン、Android は設定の画面（B3-6 の S）。内容は名前、版、ライセンスの種類、全文。全文は配布物（Android はアプリの資産）に同梱し、名前と URL だけにしない（review-15。X5-7、X7-6）。Licensee の `artifacts.json` は許諾の名前と URL を持つが全文は持たないため、全文は別に同梱する
- 依存の NOTICE（2 周目。review-15 の X5-7）：Apache License 2.0 の部品は、その jar の `META-INF/NOTICE*` を持つことがある。PC と端末は、ビルドのときに依存の jar からこのファイルを集めて配布物（Android はアプリの資産）に同梱し、画面では部品の全文と一緒に出す。NOTICE が無い部品は全文だけを出す
- adb は同梱しない（D7、N4-3）ので、platform-tools の表示は不要
- 同梱する JVM（OpenJDK のビルド）のライセンスも一覧に含める。PC は、同梱の Java 実行環境の `legal/`（モジュールごとの全文と第三者の通知）を実行時に読んでそのまま出す。全文の写しは repo にも配布物にも別に持たない（実行環境を替えても、同梱の `legal/` が正になる）
