### B4-5 PC の画面 W1〜W5（F5、F6-5）

PC のアプリはトレイに常駐し、画面は 2 枚（メインの窓と設定の窓）とする（F5-1）。画面は Compose Multiplatform（D4）。言語は日本語のみ（F6-5、暫定）。文言は 1 か所の文字列の表にまとめ、後から言語を足せる形にする（決定（未付番）。根拠：F6-5 が「暫定」のため）。

#### 画面の一覧

| W | 名 | 置き場 | 要件 |
|---|---|---|---|
| W1 | トレイのメニュー | トレイのアイコン | F5-1 |
| W2 | プレイリストの選択 | メインの窓の上段 | F5-2 |
| W3 | 端末と最後の同期 | メインの窓の中段 | F5-3、F6-2 |
| W4 | ペアリング | メインの窓の下段（ボタンで開く） | F5-4、F2-3、N1-1 |
| W5 | 設定 | 設定の窓 | F5-5、F1-8 |

#### W1 トレイのメニュー

| 項目 | 動作 |
|---|---|
| 状態の表示（1 行） | 「待機中」「同期中」「XML が読めない」「ペアリング未済」のいずれか。同期の進行は端末の通知が正で、PC は全体の曲数を知らないため件数を出さない |
| 開く | メインの窓を開く |
| ペアリングコードを表示 | W4 を開く |
| 設定 | W5 を開く |
| ログの場所を開く | B4-6 のログのフォルダをエクスプローラで開く |
| 終了 | サーバーを止めて終了。同期中は確認を出す |

- アイコンの左クリックで「開く」。警告があるときはアイコンに印を付ける（W2 の警告、W5 の警告と同じ条件）
- 起動時にメインの窓は開かず、トレイだけに入る。初回（ペアリング未済）だけ W4 を自動で開く（決定（未付番）。根拠：初回に何をするかを探させないため）
- OS ログイン時の自動起動は、W5 の項目「ログイン時に起動」で選べる。既定は有効（決定（未付番）。根拠：端末の自動起動（D13）は PC のサーバーが動いていることが前提）

#### W2 プレイリストの選択（F5-2、F1-5）

- 表示：XML の `Playlists` を一覧にする。フォルダのプレイリスト（親の Persistent ID を持つもの）は入れ子の木で表示し、フォルダは開閉できる。フォルダに属す子は字下げする
- 選択：各プレイリストにチェックボックス。フォルダのチェックは「配下をすべて選ぶ」の一括操作で、フォルダ自体の選択は保存しない（保存するのは葉のプレイリストだけ）。フォルダ内に後から足されたプレイリストは、自動では選ばれない（決定（未付番）。根拠：意図しない同期を防ぐ）
- 表示する付随情報：曲数、合計サイズ。スマートプレイリストは「スマート」の印を付け、XML の展開済みの結果を使う（F1-5）
- 対象外の表示：iTunes の組み込みの項目（ライブラリ、音楽 など）は一覧から除く（判別のキーは B2-1 の規則）
- 選択の保存：選んだプレイリストの Persistent ID の集合を、W5 の設定の保存先（B4-6）に保存する。ID が XML から消えたものは、一覧に「見つからない」と灰色で残し、利用者が外す。自動では消さない
- 変更の反映：チェックの変更は即保存し、次の P1 の応答（マニフェスト）から反映する。同期中の変更は、次の同期から有効（暫定、B2 の「差分の計算」と整合を要する）
- 警告の帯（一覧の上）：下表のとおり。警告は通知しない（トレイの印と帯だけ）

| 警告 | 条件 | 文言の要点 | E |
|---|---|---|---|
| XML が読めない | 読み直しの上限（V6）を超えても読めない、または XML が無い | 「iTunes ライブラリ XML を読めません。W5 で場所を確かめる」。端末は E4 で止まる（B2-3） | E4 |
| XML が古い | XML の更新日時が基準日数（V5）より古い | 「XML の更新が n 日前です。iTunes の設定で XML の共有が有効か確かめる」 | — |
| 選択が空 | 選んだプレイリストが 0 件 | 「同期するプレイリストが選ばれていません」。端末では消す件数の確認（B2-5）が出る。手動は画面で確認し、自動は消すを飛ばして通知で S4 へ誘導する（J9） | — |

#### W3 端末と最後の同期（F5-3、D11）

- 表示項目：端末の名前（ペアリング時に端末が申告する表示名）、状態（接続中／未接続）、最後の同期の日時、結果（成功、一部失敗、中断）、結果の件数（B2-8 の報告の項目：足した、置き換えた、消した、除外した）、失敗の種類（E の番号と名前で表示。F6-2）
- 最後の同期の情報は、P4（結果の報告。B2-8 の報告の項目。要約のみ）で端末から受けた内容を保存したもの。曲名や曲ごとの一覧は PC へ送らない（N1-6）。除外の曲の一覧は端末の画面にだけある
- 「接続中」は、直近 1 回の要求から経過した時間（V33）以内の署名つき要求があることで判定する
- 端末は 1 台（D11）。保存の形は端末の識別子（乱数 16 バイト。UUID の形で表す）をキーにした表で持ち、画面は 1 行だけ表示する。ペアリング未済は「端末がありません。ペアリングする」のボタンを出す
- 操作：「ペアリングを解除」（F2-7）。確認の後、K1 と端末の登録を消す。端末側の解除は端末で行う。端末を入れ直したときは新しい識別子になり、既存のペアリングが残るため、ここで解除してから W4 でペアリングし直す（D14）

#### W4 ペアリング（F5-4、F2-3、F2-5）

| 項目 | 内容 |
|---|---|
| ペアリングコード | 6 桁の数字を大きく表示。有効期限までの残り時間と「無効にして作り直す」ボタン。使用後と期限後（V3）は自動で無効にし、新しいコードは利用者の操作があるまで出さない |
| 試行の失敗 | 失敗回数が上限（V2）を超えたら、そのコードを無効にして帯で知らせる（N1-3）。回数は P6 の不一致で数える（B4a の B4-2） |
| MagicDNS 名 | Tailscale が有効なときだけ表示（有効の判定は、PC の機器名に付く MagicDNS 名が引けること。未確認：取得の方法）。コピーのボタン。端末の手入力の形式は B4a の B4-1 |
| 接続先の一覧 | LAN の IP とポート（例：192.0.2.10:8443 の形）。USB テザリング時の IP は、テザリングのアダプターの IP を別行で表示 |
| 指紋 | K2 の公開鍵（SPKI）のハッシュ（画面では「指紋」）を、グループ分けした 16 進で表示。端末の画面に出る指紋との見比べ用（Q5、B4a の B4-2） |

- 端末を入れ直したときは、W3 で解除してからペアリングする旨を、W4 に注として出す（端末の S2 にも同じ案内、B3 へ依頼）
- コードと鍵の値は、画面にだけ出す。ログとクリップボードへの自動コピーはしない（N1-6）。コピーのボタンは MagicDNS 名と指紋だけに付ける
- 窓を閉じるとコードを無効にする（決定（未付番）。根拠：画面に出ていないコードを残さない）

#### W5 設定（F5-5、F1-8）

| 項目 | 既定 | 備考 |
|---|---|---|
| XML の場所 | `%USERPROFILE%\Music\iTunes\iTunes Music Library.xml`（iTunes 12.x の既定。未確認：版と OS による差） | 「参照」ボタンで変更。変更時に読めるかを確かめ、結果を横に表示（E4 の判定と同じ） |
| 古いと警告する日数 | V5 | 0 で警告しない |
| ログイン時に起動 | 有効 | W1 の注 |
| サーバーのポート | V16 で固定 | 使用中なら起動時に警告し、利用者が数値で変える。自動では変えない（端末が保存した Tailscale と USB の宛先のポートが外れ、自動起動が届かなくなるため。決定（未付番））。変更後は、広告と W4 の表示が更新される（B4a の B4-1） |
| ログのフォルダ | 表示のみ | B4-6 |

- ポートが使用中のときの警告は、トレイの印と W2 の警告の帯に出す（W1 と同じ条件）
- 設定の保存と読み込みは B4-6 の形式に従う。設定の窓に「保存」ボタンは置かず、項目ごとに即保存する

### B4-6 設定とログの置き場（F6-1、F6-3、N1-4、N1-6）

#### PC（desktop）

| 種別 | 置き場 | 内容 |
|---|---|---|
| 設定 | `%APPDATA%\playlist-sync-fox\settings.json` | XML の場所、選択したプレイリストの Persistent ID、日数、ポート、ログイン時起動、`library_id` の代わりの乱数（XML に無いときだけ）、ペアリング済みの端末の表（識別子、表示名、登録日時、最後の同期の要約） |
| ログ | `%LOCALAPPDATA%\playlist-sync-fox\logs\` | 動作のログ。ファイルは日ごとではなく、大きさで切り替える |
| 鍵 | `%APPDATA%\playlist-sync-fox\secrets.bin`（DPAPI で暗号化したファイル）。K1 と K2 の秘密鍵を入れる（B4a の B4-3）（review-05 の基本設計の直し 2） | 設定のファイル（`settings.json`）には置かない（N1-4） |

- 場所の規則：利用者のユーザー領域だけに書く。インストール先（Program Files など）には書かない（F6-3。決定（未付番）。根拠：管理者権限なしで動かすため）
- 設定の書き込みは、一時ファイルへ書いてから置き換える（途中で壊れたファイルを残さない）。読めない設定は `settings.json.bad` に退避し、既定で起動して警告を出す（決定（未付番）。根拠：W2 と同じく、読めないときに黙って初期化しない）
- 設定の形式は kotlinx.serialization の JSON（B1 の技術の選定）。先頭に `schema_version` を持ち、版の上げ方は詳細設計
- ペアリング済みの端末の表は、D11 のため端末の識別子をキーにした配列で持つ。最初の版は要素が 1 つまで

#### library_id の代わりの値の保存（B2-4）

- `library_id` は XML の `Library Persistent ID` を使う。XML に無いときだけ、代わりの乱数（128 ビット。生成は暗号用の乱数の部品、B4a の B4-2 の置き場に従う）を初回に作り、`settings.json` に保存する
- 設定を消され、代わりの乱数を使っていたときは新しい値になる。端末は新しい `library_id` を見て、以前の PC と別物として扱う（Q9 の PC ごとの分離の前提。マニフェストの扱いは B2）
- `library_id` は秘密ではないが、鍵とは別の値とし、署名の鍵の導出に使わない

#### ログ（F6-1）

- 書く項目：時刻、レベル、モジュール、メッセージ、E の番号（あれば）。PC のログにはファイルのパスを出してよい（N1-6）。曲名は出してよい。鍵、コード、署名の値、証明書の秘密鍵、要求の署名ヘッダは出さない
- 上限と入れ替え：PC は V8（1 ファイル 5 MB を 3 世代）。上限を超えたら新しいファイルへ切り替え、世代数を超えた古いものを消す（F6-1）
- 外へ送らない（F6-1）。「ログの場所を開く」（W1）で利用者が自分で扱う
- レベルは 3 段（情報、警告、エラー）。詳細ログは最初の版では持たない（決定（未付番）。根拠：値の出し過ぎの防止と実装の最小化）

#### 端末（android）

| 種別 | 置き場 | 内容 |
|---|---|---|
| 設定とペアリング情報 | アプリの内部領域（Room とアプリ専用の設定） | PC の識別子、library_id、表示名、K4 の固定した証明書。詳細は B3 の表 T |
| 鍵 | Android Keystore（K3） | B4a の B4-3 |
| ログ | アプリの内部領域の `logs/` | PC と同じ項目と同じ除外。曲のパスは書かず、曲名までにとどめる（B3-4 に合わせる。N1-6 は PC のログだけにパスを許す） |

- 端末のログの上限と入れ替えは V9（1 ファイル 2 MB を 3 世代）。アプリを消すと内部領域ごと消える（D14 の前提と同じ）
- 端末のログの閲覧と共有の画面は B3-6 の S5。外へ出すのは利用者の操作による共有だけ

### B4-7 Releases での配布（N4、Q12、D12）

#### PC：配布物の形の比較（N4-1、Q12、J13）

| | jpackage のインストーラ（exe または msi） | jpackage のアプリイメージの zip | JVM なしの zip |
|---|---|---|---|
| 利用者の JVM | 不要（同梱） | 不要（同梱） | 必要 |
| 導入の手間 | 実行して導入。ショートカットの作成と登録が付く | 展開して実行 | 展開して実行。JVM を用意 |
| ビルドの前提 | jpackage の実行に WiX Toolset（3.0 以上）が必要（facts-jvm 3b。入手は未確認） | JDK の jpackage だけ（`--type app-image`。facts-jvm 3a。WiX は不要とは書かれていない：未確認） | Gradle だけ |
| 大きさ | 大（JVM 込み） | 大（JVM 込み） | 小 |
| 署名なしの警告 | 出る（SmartScreen。回避は署名のみ。署名の有無と費用は未確認、Q12） | 出ることがある（未確認） | 出ることがある（未確認） |
| アンインストール | OS の標準の画面から | フォルダを消す | フォルダを消す |

- 決定（J13、2026-11-05 先生）：最初の版は「jpackage のアプリイメージの zip」、コード署名なし。JVM 同梱で利用者が JVM を入れずに済み、ビルドの前提が最小で、署名なしでも導入手順を README に書けば足りる（D12 の利用者は最初は作者）。インストーラは、ログイン時の自動起動の登録（W5）と配布の利用者が増えた時点で足す（暫定、Q12）
- zip の中身：実行ファイル、JVM、ライセンスの一覧（本項の「OSS ライセンスの表示」）、README。展開先は利用者が決め、設定とログは B4-6 のとおりユーザー領域に出る
- ログイン時の起動は、zip でも実装できる（利用者のスタートアップに登録する。方式は詳細設計）
- コード署名：最初の版は付けない。理由：費用と手間が配布の規模に合わない（根拠は D12）。SmartScreen の警告は README に書く（暫定、Q12）

#### Android：APK の署名と鍵の置き場（N4-2）

- APK は release ビルドを自分の署名の鍵（keystore）で署名する。同じ鍵で署名した APK でないと更新（上書き）できないため、鍵を失うと更新できない
- 鍵の置き場：先生の手元の暗号化した保管先に置き、repo に入れない。CI に置く場合は、Secrets に登録した鍵を環境変数で渡す形に限り、ログに出さない（未確認：CI の機能の細部は B1 のビルド・CI の方針に合わせる）
- 鍵のバックアップを別の場所に 1 つ持つ（決定（未付番）。根拠：失うと更新できない）
- Play ストアへ移る場合は、Play 側の署名の仕組みを使う（将来、D12。未確認）。その時の鍵の扱いは別に決める

#### 下書き Release の流れ（B1 の依頼）

| 段階 | 内容 | 担当 |
|---|---|---|
| 1 | 版のタグを打つ（形式は B1 の稿の履歴の約束に合わせる） | 手動 |
| 2 | CI がタグを契機に、PC の zip と APK を作る。APK は署名の鍵が CI にあるときだけ署名する | CI |
| 3 | CI が「下書き」の Release を作り、配布物とチェックサム（SHA-256 の一覧）を付ける | CI |
| 4 | 手元で APK を実機に入れ、B4-8 の確認の表（C-1〜C-12）の該当項目を確かめる | 手動 |
| 5 | 下書きを公開する。公開の前に、repo が public であることを確かめる（D12） | 手動 |

- 公開の操作は手動のままにする（決定（未付番）。根拠：実機の確認の後に公開するため、CI からは公開しない）
- Release の本文には、変更の要点、PC の導入手順、APK の「提供元不明のアプリ」の許可の手順を書く（F6-4：更新の確認は持たないので、案内は Release の本文が担う）
- チェックサムは配布物の取り違えの確認用。署名の代わりではない

#### OSS ライセンスの表示（N4-4）

- 使う OSS（Kotlin、Ktor、Room、Compose、JmDNS か代替など。名前は B1 の技術の選定に従う）のライセンスの一覧を、ビルド時に生成して配布物に同梱する（Gradle のプラグイン Licensee（`app.cash.licensee`）を使う。`artifacts.json` を出力し Android のアセットへ同梱できる。facts-jvm 8b。JSON の項目の一覧は未確認）
- 表示の場所：PC は W5 の「ライセンス」ボタン、Android は設定の画面（B3-6 の S）。内容は名前、版、ライセンスの種類、全文
- adb は同梱しない（D7、N4-3）ので、platform-tools の表示は不要
- 同梱する JVM（OpenJDK のビルド）のライセンスも一覧に含める

### B4-8 テストの方針（N5）

#### 層ごとの方針

| 層 | 方針 | 要件 |
|---|---|---|
| shared | 純粋関数の単体テストを中心にする。対象：マニフェストの組み立てと直列化、差分の計算（3 種と消す規則）、m3u8 の生成（相対パス、文字コード）、署名の生成と検証、鍵の導出、再送防止の判定、ペアリングの手順の状態遷移 | N5-1 |

- 実行：変更した層のテストだけを手元で回す。全層は CI（B1）で回す
