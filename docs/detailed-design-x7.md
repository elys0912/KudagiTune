### X7-1 画面 S1〜S6

#### X7-1-1 共通の約束

1. 画面は T の読み取りと、X6 が公開する進行の状態（SyncProgress）だけを見る。MediaStore と HTTP を直接呼ばない
2. T の読み取りのうち、Room の購読（Flow）で行うのは S1 の表示（T2、T3、T4、T8）だけで、書き込みの完了で自動に再描画する。S4・S5 は、画面を開いたときと操作の後に読み直す（購読しない）
3. 画面の操作は ViewModel の関数を呼ぶだけにする。処理の実体は X6（同期）、X4（ペアリング）、X7-2（発見）、X7-5（ログ）が持つ
4. 画面の遷移は S1 を起点にする。S2〜S5 から戻るとき S1 に戻る。同期の開始は S3 へ進み、完了または中断で S4 へ進む
5. ペアリングの有無は T4 の行の有無で決める（T4 の主キーは `device_id`。端末は 1 台。行は最大 1）
6. 曲名と PC の名前は画面に出してよい。曲のパスは出さない（B3-4）
7. 配色は OS の設定（ライト・ダーク）に従う（D20。foundation の `isSystemInDarkTheme()`）。Material は入れず、色の組は `CompositionLocal` で配る。部品（文字、ボタン、主ボタン、入力欄、確認、カード、棒）は 1 か所に置き、全部の画面が同じ部品を使う。書体は端末の既定（数字とログは monospace。B1-9 の 19。Q14 で決定）

#### X7-1-2 S1 一覧

状態（ペアリングの有無と最後の同期の有無の組み合わせ）：

| 状態 | 条件 | 表示 | 同期ボタン |
|---|---|---|---|
| 未ペアリング | T4 に行が無い | 「ペアリングしてください」の表示だけ | 押すと S2 |
| 未実行 | T4 に行が有り、T3 に行が無い | PC の名前（`pc_name`）、接続先、「まだ同期していません」 | 押すと S3 |
| 実行済み | T4 と T3 に行が有る | PC の名前、接続先、最後の同期の日時と結果（T3 の `ended_at` が NULL でない最新の行。NULL の行の扱いは下）、プレイリストの名前と曲数（T2） | 押すと S3 |
| 同期中 | X6 の同期が動いている | 上に加え「同期中」の表示 | 「進み具合を見る」（S3 へ） |

- 接続先：T4 の `last_endpoint`（値は方式。`lan`、`tailscale`、`usb`）が指す方式の `endpoint_*` の値。空なら「未接続」（J30。2026-11-06）
- T8（選択）が空のときは、プレイリストの一覧の代わりに「同期するプレイリストを選んでください」の案内を出す（選択は端末の操作。S6。F3-11）。T8 が空でなく、T2 が空（まだ書いていない）ときは、選んだ件数と、まだ同期していない旨を出す
- `ended_at` が NULL の行は実行中の行（`result` は `failed` で作る。X6-1）か、まだ閉じていない強制終了の跡。同期中なら出さず、その前の行を出す（その前の行が無い最初の同期の最中は「まだ同期していません」を出す）。同期中でなければ「中断」として出し、日時は `started_at` とする（X6-3 の 1 の 2）
- 最後の同期の結果の表示語は T3 の `result` の値に 1 対 1 で対応させる（success、partial、interrupted、failed、not_started。対応表は X3-5）
- T3 の `trigger` の表示語は `manual`、`auto` の 2 つだけ。`continue` は使わない（J21）

操作と処理：

| 操作 | 処理 |
|---|---|
| 同期ボタン | 未ペアリングの間は「ペアリング」と表示し、S2 へ。そうでなければ、まず始められるかを確かめる（X6-3 の手順 0 と同じ判定）：T8 が空なら同期を始めず S6 へ案内する（文：同期するプレイリストを選んでください）。保存先が SD で SD が見つからないなら、同期を始めず案内を出し（文：保存先の SD が見つからない。S5 で保存先を確かめる）、本体へ切り替えない。どちらでもなければ X6-3 の手動の同期の開始を呼び、S3 へ |
| 結果の表示 | S4（T3 の最新の行。NULL の行の扱いは上）へ |
| プレイリストを選ぶ | S6 へ（ペアリング済みのとき） |
| 設定 | S5 へ |

- 手動の同期の開始の前に、通知の権限の確認（X7-4）を行う。求めるのは同期が実際に始まるとき（ペアリング済みで、選択があり、保存先があり、自動が実行中でない）だけで、未ペアリングの「ペアリングする」（S2 へ進む操作）、選択が空で S6 へ案内するとき、保存先が無いとき、実行中の自動があって S3 へ入るときは求めない（review-15。X7-3。TA-250）。同期ボタンのたびに、許可されるか二度拒否になるまで求める（X7-4-2。「1 回だけ」ではない。X7-8）。拒否でも同期は続ける
- 同期ボタンの後、画面は P1 の前に、実行中の自動の同期が無いかを確かめる。動いていれば、確認を出さずに S3（進行）に入る。自動は自動のままで（抑止も「消す」の飛ばしもそのまま）、終わった後に必要なら利用者がもう一度押す（J34。X6-4）
- 「消す」の確認は、手動の同期のときに画面側が行う。設定が ON なら、「消す」が 1 件以上のとき必ず確認する（D19。2026-11-07）。手順：
  1. 同期ボタンの後、実行中の自動が無ければ、設定「PC に無い曲を端末から消す」（T7 の `delete_missing_enabled`）を見る。OFF なら消さないので、P1 を取らず、確認なしでワーカーを起動する。ON なら、画面は X6 の口で P1（マニフェスト）の取得と差分の計算を行い、消す件数を得る（`removalGate` は使わない。自動の判定だけに使う）。接続先は X6-3 の 2 の 2 の到達確認の関数で選ぶ（画面側に別の選び方を持たない。`last_endpoint` の更新も同じ）
  2. P1 の取得か差分の計算に失敗したとき（届かない、E2、E4。ほかの P1 の失敗（E6 など）も同じ）は、確認を出さずにワーカーを起動する。届かなかったとき（全部の接続先が応えず、証明書の不一致が 1 つも無いとき）はその旨（`reach_failed`）を添え、ワーカーは同じ接続の試行を繰り返さない。不一致があったときは添えず、ワーカーが E2 を記録する（X6-3 の 6 の 1）。ワーカーが失敗を E として T3 に記録し、S4 に出る（X6-3）
  3. `toRemove` が 0 件なら確認を出さずにワーカーを起動する
  4. `toRemove` が 1 件以上なら、`removalGate` によらず S3 の前の確認の画面に消す件数を出す（D19）
  5. 承認されたら、承認した件数を添えて手動の同期の開始を X6 へ渡し、S3 へ進む。ワーカーは P1 を取り直し、消す件数が承認した件数を超えれば消すのを飛ばす（承認の有効範囲は 1 回。V48。X6-3 の 6）。承認の後の起動のときに自動が動いていた場合は、新しい仕事を作らず承認は使われない。S3 に「承認は使われなかった。終わった後にもう一度押す」を出す（X6-4 の 1）。前回の終了の進捗を消すのは、手動の開始で新しい仕事を作ったときだけで（先に出た新しい進捗は消さない）、新しい仕事を作らなかったときは走っているワーカーの進捗を消さない（TA-133、TA-264）
  6. 取り消されたら、消すだけを飛ばして同期を始め、S3 へ進む（足す、置き換える、m3u8 は行う。J26）

#### X7-1-3 S2 ペアリング

状態：

| 段 | 条件 | 表示 | 操作 |
|---|---|---|---|
| 探索中 | 画面の表示から V13 の間 | 発見した PC の一覧（空でもよい）、手入力欄 | PC を選ぶ、宛先を入力する |
| 宛先の確定 | PC を選んだか、宛先が検査を通った | ペアリングコードの入力欄（V1 の桁数。PC のペアリングコード。確認コードとは別）。コードを送って P5 の応答が返った時点で、PC の証明書の確認コード（X4-4 の表示形式。表示だけ。保存の前）を出す | コードを入力して送る |
| 完了 | P6 の成功で T4 と Keystore への保存が確定（X6-6） | 保存の完了、PC の名前、「違うと思えば PC の W3 と端末の S5 の両方で解除する」の案内。T1・T2 が空のときは「以前このアプリを使っていたなら、先に以前の曲の整理を」の 1 行（S5 の「以前の曲の整理」。J38） | S1 へ |
| 試行の上限 | V2 に達した、または `pairing_locked`（V4 の待ちもここに含める） | 試行の上限の案内（コードの作り直しを PC で行う） | 戻る |
| 待ち | V32 の待ち（429）に当たった | 待ちの案内 | 戻る |
| 失敗 | 接続、検査、鍵の導出の失敗（E の種類と `detail` を下の表で表示語に直す） | 原因の種類 | やり直す |
| 入れ直しの案内 | 新規を PC が受け付けない応答（`device_exists`。D14） | 「PC に登録が残っている。PC の W3 で解除してから」（入れ直したとき、P6 の後に端末の保存が失敗したときを含む） | 戻る |

操作と処理：

| 操作 | 処理 |
|---|---|
| 一覧から PC を選ぶ | X7-2 の接続先の候補に追加し、「宛先の確定」へ |
| 宛先を入力 | X7-2-3 の検査。通れば「宛先の確定」へ。通らなければ理由を入力欄の下に出す |
| コードを送る | X4-2 のペアリングの開始を呼ぶ。P6 の成功で X6-6 の保存（T4 の行の作成、K3 の取り込み）を呼び、「完了」へ進む。結果で段を進める |

- 確認コードは P5 の応答の時点で表示するだけで、見比べの操作は持たない。保存は P6 の成功で確定する（J27。2026-11-06）
- 確認コードは、P5 の接続で見た PC の証明書の SPKI の SHA-256 の値から、shared（M1）の `formatFingerprintOfHash`（X4-4。先頭 12 バイトを 4 桁ずつ区切る）で作る。S2 と S5 は同じ関数を呼び、端末に別の実装を持たない。PC の確認コード（X5-5）と同じ値になる（review-15。X4-5）
- P6 の成功の前に画面を離れたとき、または失敗したときは、T4 と Keystore に何も書かず、メモリ上の一時の鍵を捨て、接続を切る。「完了」の後に画面を離れても保存は取り消さない

E2 の `detail`（X4-3、B4-4 の 8 の表）ごとの表示（S2 と S3 で共通。S4 は T3 の `result_json` の `error_detail`（X6-1。値は `clock_skew`、`replay`、`pin_mismatch`、`rate_limited`、空）から、この表の語を選ぶ。`error_kind` だけでは時計のずれと証明書の変更を見分けられない）：

| `detail` | 出る場面 | 表示 |
|---|---|---|
| `clock_skew` | 署名付きの要求（X4-3） | 「端末と PC の時計が違う」。時刻を合わせてやり直す案内 |
| `replay` | 署名付きの要求 | 「通信が重複した」。もう一度試す案内（端末は新しい nonce でやり直す） |
| `rate_limited` | 署名付きの要求（429。V32 の間） | 「要求が続いたため PC が一時的に断った」。時間をおいて同期する案内（再ペアリングは要らない。J35） |
| `pairing_closed` | P5 | 「PC がコードを表示していない」。PC でコードを出してからやり直す案内。S2 だけ |
| `pairing_locked` | P5 | S2 の「試行の上限」の段。S2 だけ |
| `device_exists` | P5 | S2 の「入れ直しの案内」の段。S2 だけ |
| （空。`detail` なしの 401） | 署名が合わない、未登録の端末 | 「ペアリングをやり直してください」（S3 では再ペアリングへ誘導。X6-6）。PC の W3 と端末の S5 の両方で解除してから再ペアリングする案内（S1 は T4 が残る間 S2 へ入れないため） |
| `pin_mismatch`（証明書の固定の不一致。PC の応答に `detail` は無い） | 到達確認、署名付きの要求（X6-5） | 「証明書が変わった」。PC の W3 と端末の S5 の両方で解除してから再ペアリングする案内（B4-3 の 1） |
- コードは画面の状態に長く持たない。送信の直後に入力欄を空にし、ログに書かない（N1-6）。画面の回転で保つ状態（保存して復元する状態）にも入れない。回転するとコードは入力し直す。手入力の宛先などは、回転で保つ

#### X7-1-4 S3 同期の進み具合

状態は X6 の SyncProgress をそのまま写す。

| 項目 | 型 | 必須 | 意味 |
|---|---|---|---|
| `stage` | 列挙 | 要 | `connecting`（始めの整理と到達確認）、`manifest`、`diff`、`capacity`、`transfer`、`playlist`、`finished` |
| `done_count`、`total_count` | 整数 | 要 | 完了／全体の件数 |
| `done_bytes`、`total_bytes` | 整数 | 要 | 転送済み／全体の容量 |
| `current_title` | 文字列? | 任意 | 現在の曲名。`transfer` のときだけ |
| `shortage_bytes` | 整数? | 任意 | 容量不足の不足分。`capacity` で足りないときだけ |
| `near_limit` | 真偽 | 要 | 時間の上限が近い（B3-5 の 5 の注記を出す） |
| `outcome` | 列挙? | 任意 | `finished` のときの T3 の `result` |
| `error_detail` | 列挙? | 任意 | `finished` で E2 のときの `detail`（`clock_skew`、`replay`、`pin_mismatch`、`rate_limited`、空。X6 が渡す。表示は X7-1-3 の表） |
| `tracks` | 行の並び | 要 | 曲ごとの行（X6-3 の SyncProgress。`title`、`size`、`state`、`received_bytes`、`error_number`）。`transfer` の前は空。D22 |

- `near_limit` の立て方と閾値（V17）は X6-3 が決める。X7 は表示するだけ。V17 で同期は区切らない（注意の表示だけ。J33）
- 画面の配置（D21、D22）：上から、見出しと全体の棒（`stage` ごとの見出し、割合 `done_bytes / total_bytes`、件数と容量、失敗の件数）、曲ごとの一覧（`LazyColumn`。残りの高さ）、ログの欄（高さ 150 dp）、「中断する」
- 曲ごとの行：状態の印（完了＝成功の色のチェック、転送中＝アクセントの下向きの矢印、待機＝薄い時計、失敗＝失敗の色の×）、曲名（1 行で切る。完了は薄い文字）、右に大きさ（転送中は「受け取った量 / 大きさ」）。転送中の行は「転送中の行」の地の色で、曲名の下に細い棒。失敗の行は曲名の下に理由（E の番号の語。X7-1-5 と同じ語）を失敗の色で出す
- 一覧は転送中の行が見えるように送る（転送中の行が変わったとき、その行を見える位置へ送る。利用者が触っている間は送らない）
- ログの欄：X7-5 の画面の欄（直近 V55 行）を写す。新しい行が下。行は 時刻（端末の地方時の `HH:mm:ss`）とメッセージ。警告とエラーの行はその色
- 容量不足の案内、`near_limit` の注記、E2 の案内は、見出しの下に出す
- 操作は「中断」だけ。X6-3 の中断を呼び、`finished` を待って S4 へ進む
- `shortage_bytes` が有るとき（容量不足。X6-3 の 5 は `getAllocatableBytes`）は、不足分と `ACTION_MANAGE_STORAGE` の案内（空きを作る画面を開く操作）を出す（J21）
- `finished` になったら自動で S4 へ進む。画面を離れていた場合は通知から S4 へ入る（X7-3）

### X7-2 発見と手入力

#### X7-2-1 NSD の使い方

| 項目 | 内容 |
|---|---|
| 部品 | `NsdManager` の発見（`discoverServices`）と解決（`resolveService`）を包む `PcDiscovery`（M4 の発見層） |
| サービスの型 | `_psfox._tcp`（B4-1 の 1）。V の番号は付かない固定の名前（B4a の決定） |
| 入力 | 開始と停止の指示 |
| 出力 | `DiscoveredPc` の流れ（下の表） |
| 副作用 | S2 の発見は、画面が S2 のときだけ開始し、S2 を離れたら停止する。このほかに、同期の到達確認（X6-3 の 2。V14）で、`pid` から接続先を引き直すときに使う。同期の中のそれ以外では発見しない |

`DiscoveredPc`：

| 項目 | 型 | 必須 | 意味 |
|---|---|---|---|
| `service_name` | 文字列 | 要 | NSD のサービス名（`psfox-` と pc_id の先頭 8 桁） |
| `host` | 文字列 | 要 | 解決した IPv4 |
| `port` | 整数 | 要 | SRV のポート |
| `protocol_version` | 整数 | 要 | TXT `v` |
| `pc_id_prefix` | 文字列 | 要 | TXT `pid` |
| `pairing_open` | 真偽 | 要 | TXT `pair` が 1 |

手順：

1. 開始で `MulticastLock` を取り、発見を始め、V13 のタイマーを置く。`MulticastLock` は T 拡張 7 より前の端末で mDNS を受けるために要る（確認済み。facts-android 7-1）。停止で必ず放す
2. 見つかったサービスのうち、型が一致するものを解決する（複数は 1 件ずつ順に。解決の同時実行を避ける）
3. 解決に失敗したサービスは捨てる。次の発見で再び出れば再度解決する
4. TXT の `v` を整数に読む。読めない、または知らない版（端末が対応する版より新しい）は一覧に出さない（B4-1 の 1）
5. TXT の `pid` と `pair` を読む。欠けたものは捨てる
6. ペアリング前（T4 に行が無い）は `pairing_open` が真のものだけを一覧に出す
7. ペアリング済みの同期（X6）は、T4 の `pc_id` の先頭 8 桁を `pc_id_prefix`（TXT `pid`）で探し、前方一致が合うものを使う。見つかった `service_name` が T4 の `endpoint_lan` と違えば書き直す（NSD の名前の衝突でインスタンス名が変わっても引き直せる）
8. V13 が過ぎても 1 件も無ければ「見つからない」と手入力欄を目立たせる表示にする。発見は続けてよい

- TXT の値は信用しない。接続後の固定の証明書の確認（N1-5）が本体
- 複数の PC が見つかったときは一覧に並べる。端末は 1 台の PC としかペアリングしない（Q9。最初の版は 1 台の PC で確定）
- `MulticastLock` の取得には `CHANGE_WIFI_MULTICAST_STATE`（通常の権限）を宣言する（X7-4-1。権限名は WifiManager の文書で未確認）。T 拡張 7 以降は前面のアプリについてシステムが受信を管理する

#### X7-2-2 USB テザリングと Tailscale

- Tailscale では mDNS を使わない（B4-1 の 1。未確認）。手入力に頼る
- テザリングは mDNS で見つかればそれを使い、見つからなければ手入力（J12）。走査は持たない
- 手入力で通った宛先は、接続が成功した後に T4 の列へ保存する（X7-2-4）

#### X7-2-3 手入力の検査（B4-1 の 2）

入力は文字列 1 本。検査は次の順で行い、最初に外れた理由を返す。

1. 前後の空白を除く。空なら「入力が空」
2. 使える文字は英数字、`.`、`-`、`:` だけ。他を含めば「使えない文字がある」（`https://`、`/`、空白、`@` はここで外れる）
3. `:` が 2 個以上なら「形が違う」（IPv6 は扱わない。B4-1 は IPv4 と MagicDNS 名）
4. `:` が 1 個なら、後ろをポートとする。数字だけで 1〜65535 でなければ「ポートが違う」。前は空でないこと
5. `:` が無ければポートは V16 とする
6. ホスト部が数字と `.` だけなら IPv4 として検査する。4 つの 0〜255 の整数でなければ「IP の形が違う」
7. それ以外は名前として検査する。先頭と末尾が `.` か `-` なら「名前の形が違う」。連続する `.` も外す。各ラベルは 1 文字以上 V49 以内、全体は V50 以内（V49、V50 は未確認）
8. 通れば `ManualEndpoint`（`host`、`port`）を返す

- 検査は形だけ。到達できるかは接続の試行で分かる（V29、V53 の待ち）
- 名前解決は端末の OS に任せる（MagicDNS 名が引けることは確認済み。2026-11-05 先生）

#### X7-2-4 T4 の 3 列への保存

| 方式 | 列 | 書く値 | 方式の判定 |
|---|---|---|---|
| LAN | `endpoint_lan` | NSD の `service_name` | 発見の結果で成功したとき |
| Tailscale | `endpoint_tailscale` | `host:port`（MagicDNS 名） | 手入力で、ホストが名前のとき |
| USB | `endpoint_usb` | `host:port` | 手入力で、ホストが IPv4 のとき |

1. 保存は接続の成功の後に行う（ペアリングなら T4 の行の作成と同時。同期なら成功した宛先の更新）
2. 方式の判定は、入力の形（名前か IPv4 か）で行う。ネットワークの種別から推測しない
3. 同じ列には最後に成功した 1 つだけを持つ。上書きする
4. 成功した方式（`lan`、`tailscale`、`usb`）を T4 の `last_endpoint` に保存する（J30）
5. 保存の呼び出しと失敗時の扱いは X6-3 の 2（到達確認での接続先の候補の順。B4-1 の表の 1〜3 の順）に合わせる
6. `usb` の列は「IPv4 の手入力」の意味で、LAN の IP を手入力しても `usb` の列に入る（方式の判定は入力の形で行うため）。S1 の接続先の表示と結果の方式の語も、この方式の語になる
7. T4 の `pc_name` は、LAN は NSD の `service_name`、手入力は入力のホスト部（名前または IPv4）とする。P5 の応答に PC の名前は無い（PC のホスト名を出さない。B4-1 の 1）。S1・S2・S5 はこの値を出す

### X7-3 通知

#### X7-3-1 通知の種類

| 種類 | チャンネル | 重要度 | 表示 | 操作 |
|---|---|---|---|---|
| 持続（同期中） | `sync_progress` | 低（音と振動なし） | 件数（完了／全体）、容量（転送済み／全体）、現在の曲名、進行の棒 | 「中断」、本体のタップで S3 |
| 終了（手動） | `sync_result` | 既定 | 結果の区分と件数 | タップで S4 |
| 終了（自動） | `sync_result_quiet` | 低（静か） | 同上 | タップで S4 |

- 持続の通知は X6-3 のワーカーが前面に昇格するときの通知。内容は X7 が作り、ワーカーの `setForeground` へ渡す（作る関数は `SyncNotificationBuilder`：入力は SyncProgress、出力は通知。ワーカーは、手動は開始直後に、自動は到達確認が通り、自動の抑止で終えないと決まった後（X6-3 の 2 の 7）に渡す（J46）。X7-3-2 の 5）
- 終了の通知は、手動か自動かで入れるチャンネルを分ける。チャンネルは初回の起動で作る
- 自動の同期が「消す」を飛ばしたときは、終了の通知に「確認が要る」の旨を足す（J9）
- 容量不足で止まったときは、終了の通知に `ACTION_MANAGE_STORAGE` の案内を足す（タップで空きを作る画面。J21）

#### X7-3-2 持続と終了

1. 持続の通知は、ワーカーが前面に昇格した時点から出し、同期が終わるか中断で外す
2. 同期が終わったら持続の通知を外し、終了の通知を出す
3. 終了の通知は 1 つだけにする（同じ通知の番号で更新する。積み上げない）
4. 利用者の中断（T3 の `interrupted`）の終了の通知は、手動のときは出し、利用者が自分で押したので音は出さない。自動のときも、静かな終了の通知を出す
5. 自動の起動で PC に届かず、または抑止（V19、鍵の不一致の E2、E3、同じ `content_digest`）で、何もせず終わった実行（D13）は、前面の通知も終了の通知も出さない（J10。T3 にも残さない）
6. 時間の上限（E7）で止まったときの終了の通知は「続きは次の同期で行う」を添える
7. T3 に残して終えた失敗は、手動も自動も終了の通知を出す（手動の E1、手動・自動の E2、P3 の E4・500。X6-3 の 2 の 1b、3、4、4b）。自動は静かな通知。5 の「何もせず終わった実行」とは別。S3 は `finished` で S4 へ進む

#### X7-3-3 更新間隔

- 持続の通知は、前回の更新から V28 以上の間隔が空かなければ更新しない
- 手順：
  1. SyncProgress の変化を受ける
  2. 前回の更新の時刻との差が V28 以上なら通知を更新し、時刻を記録する
  3. 満たなければ最新の状態だけを保持し、捨てる（遅延の更新はしない）
  4. `stage` の変化と `finished` は間隔に関わらず更新する
- S3 の画面は通知と別に、状態の変化ごとに描く（間隔を設けない）

#### X7-3-4 権限

- `POST_NOTIFICATIONS`（Android 13 以降）は X7-4 の手順で求める
- 拒否でも同期は動く（B3-5）。通知が出ないだけ
- 拒否時の前面サービスの通知は、通知ドロワーに出ず、タスクマネージャーに出る（確認済み。facts-android 5）。前面サービスの起動に `POST_NOTIFICATIONS` は不要で、通知の提示は必須
- 拒否されたとき S5 に「通知が出ない」の表示を 1 行足す（J21（a））

| `CHANGE_WIFI_MULTICAST_STATE` | する | 常に（通常の権限。X7-2-1 の `MulticastLock` のため。基本設計の直し 4） |
| `SystemForegroundService`（`service` 要素の上書き） | する | `tools:node="merge"`、`foregroundServiceType="dataSync"`。targetSdk 34 以上で長い処理の Worker に必要（facts-android 1-5。`dataSync` を書く例は文書に無い） |
| `SyncForegroundService`（`service` 要素） | する | `foregroundServiceType="dataSync"`、`exported="false"`。Worker の代わりに前面サービスで直接動かす余地（基本設計の直し 18）。C-10 の結果で使うか決める。実装はあるが、`SyncScheduler` はまだ呼ばず、同期は Worker で動かす |

- minSdk は 30（土台）。Android 11・12 が範囲に入るので `READ_EXTERNAL_STORAGE` の宣言は要る
- 前面サービスの種別（`dataSync`）の宣言は上の `SystemForegroundService` の上書きの行に置く。X6-4 は X7-4-1 を参照する
- アプリの表示名（`application` の `android:label`。文字列資源 `app_name`）は KudagiTune（review-15）。表示名だけを改め、`applicationId` とパッケージ名は変えない。画面の上の帯も同じ文字列資源を使う
- アプリのアイコン（review-15）：アダプティブアイコン（`mipmap-anydpi-v26` の `<adaptive-icon>`。背景は色の資源、前景は密度ごとの画像。`application` の `android:icon`。`android:roundIcon` は宣言しない）。図柄は、同期の輪に狐の耳と尻尾を付けたもの（耳は幅広で内側が白く、尻尾は先が白い。PC のアイコンと同じ図柄）。端末の形（円、角丸など）に切り抜かれても欠けないよう、前景は安全域（中央の 66 dp）に収める。ランチャーのアイコンと、設定のアプリ情報で同じ図柄を使う。PC のトレイの小さい版（16・32 px の平らな簡略版）は PC だけで使う（X5-5）
- `ACCESS_LOCAL_NETWORK` は Android 17 以降で targetSdk 37 以上のときだけ実行時権限が必須（NsdManager も対象。facts-android 7-2）。最初の版の targetSdk は 36 以下（J21）で、土台は targetSdk 36（`gradle/libs.versions.toml`、2026-11-06）。`INTERNET` で暗黙に許可されるため宣言しない
- 宣言しない権限は B3-7 の「求めない権限」の表のとおり（`WRITE_EXTERNAL_STORAGE`、`MANAGE_EXTERNAL_STORAGE`、`MANAGE_MEDIA`、位置情報、`ACCESS_WIFI_STATE`、`RECEIVE_BOOT_COMPLETED`）

#### X7-4-2 実行時の要求

| 権限 | 求める条件 | 求める場所 | 拒否のとき |
|---|---|---|---|
| `POST_NOTIFICATIONS` | Android 13 以降で、手動の同期が実際に始まるとき（ペアリング済みで、選択があり、保存先があり、自動が実行中でない。X7-1-2）の開始の前に未許可 | S1（と S4）の同期ボタンの押下。未ペアリングの「ペアリングする」、選択が空で S6 へ案内するとき、保存先が無いとき、実行中の自動があるときは求めない（review-15。X7-3。TA-250） | 同期を続ける。通知なし |
| `READ_MEDIA_AUDIO`（13 以降）／`READ_EXTERNAL_STORAGE`（12 以下） | S5 の「以前の曲の整理」の「許可して一覧を出す」を押したとき（S5 を開いただけでは求めない） | S5 | 項目を閉じる。同期に影響なし |

手順（実行時の要求の共通）：

1. 許可の状態を確認する。許可済みなら要求しない
2. 「再度の要求を OS が出さない状態」（二度拒否）のときは要求せず、設定アプリへの案内を出す。案内は、画面を移っても消えないトースト（OS の `Toast`）で出す。画面の状態の `message` は画面を移ると消え、S3 は描かないため使わない（review-15。X7-1）
3. 要求し、結果を ViewModel に返す
4. 拒否の結果は端末内に覚え、同じ起動の間は再び求めない（次の起動の同期ボタンで、また求める）

- 同期の本体（MediaStore への書き込み、読み戻し）には実行時の権限を求めない（B3-7）
- ログのファイルへの保存（X7-5-2）には権限を求めない。OS の保存先の選択（`ACTION_CREATE_DOCUMENT`）が書き込み先を渡す
- 通知の許可は、手動の同期が実際に始まるとき（ペアリング済みで、選択があり、保存先があり、自動が実行中でない）の開始の前に、許可されるか二度拒否になるまで、同期ボタンのたびに求める（同じ起動の間の拒否を除く。「1 回だけ」ではない。review-15。X7-8）。未ペアリング（S2 へ進む）、選択が空（S6 へ案内する）、保存先が無い（案内を出す）は同期が始まらないので求めない。実行中の自動がある場合は、確認を出さずに S3 へ入るだけで、手動の同期は始まらないので求めない（review-15。X7-3。TA-250）。自動の起動の中では求めない（画面が無い）

### X7-5 ログ

#### X7-5-1 形式

| 項目 | 内容 |
|---|---|
| 置き場 | アプリの内部領域の `logs/`（B4-6） |
| 書式 | 1 行 1 件。行の項目はタブ区切りで、日時（UTC の ISO 8601、`Z`）、レベル、モジュール、メッセージ、E の番号（あれば）の順（PC のログと同じ項目。B4-6、X5-4 に合わせる） |
| レベル | 情報、警告、エラーの 3 段（B4-6）。詳細ログは持たない |
| 上限 | V9（1 ファイル 2 MB を 3 世代）。書き込みの前に大きさを見て、超えたら世代を 1 つずつ送り、最古を消す |
| 有効 | 常に書く。切り替えの設定は持たない（T7 に `log_enabled` は無い。S5 に切り替えも置かない。review-15。J21（a）の「既定は真」を、切り替え自体の廃止に改めた） |
| 書かないもの | 鍵、ペアリングコード、曲のパス、署名の値（N1-6）。曲名はメッセージに出してよい（曲名まで） |

- メッセージの固定の部分は変えず、可変の値は後ろに足す（検索のしやすさ）
- 書く側は 1 つの `AppLog`（入力：レベル、モジュール、メッセージ、E の番号（任意）。出力：なし。副作用：ファイルへの追記、世代の送り）。書き込みは専用の 1 スレッドで行い、同時の書き込みで行が崩れない
- 書き込みに失敗してもアプリの処理は止めない（ログの失敗を同期の失敗にしない）
- 自動で PC に届かず何もせず終わった実行は、診断のログに 1 行だけ書く（J10）
- 画面の欄（D21）：ファイルへ書く行と同じ行（書かないものを伏せた後の行）を、メモリの直近 V55 行にも入れて流す（`StateFlow`）。ファイルの書き込みに失敗しても入れる。プロセスの起動の前の行はファイルから読み戻さない。同期のワーカーと画面は同じプロセスなので、同じ `AppLog` の流れを見る

#### X7-5-2 閲覧と共有

| 操作 | 処理 |
|---|---|
| 閲覧 | 世代を新しい順に読み、新しい行を上にして表示する。大きさに関わらず、末尾から最大 V51 行を読む（専用の値。J21） |
| 共有 | 利用者の操作による共有。新しい世代から読み、末尾の V51 相当の行までに切った 1 つのテキストを作り、OS の共有の選択（Intent の送信）へ渡す（J43）。端末の外へは、共有とファイルへの保存のほかには出さない（B4-6） |
| ファイルに保存 | 利用者の操作による保存（review-15）。確認の画面（共有と同じ「ログには曲名が含まれます」）の後、OS の保存先の選択（`ACTION_CREATE_DOCUMENT`、MIME `text/plain`。拡張子は .txt）で場所とファイル名を選ばせ、選ばれた場所へ UTF-8 のテキストとして書き出す。既定のファイル名は `kudagitune-log-<日時>.txt`（端末の地方時の `yyyyMMdd-HHmmss`）。範囲はログ全体：`logs/` の全世代を、古い世代から新しい世代へ順に、行の順（古い行が先）のまま 1 つにつなぐ。V51 での切り詰めはしない（共有とは別）。本文の読み取りは、ログの書き込みと同じ executor で行い、結果を待つ（世代送りの途中のファイルを読まない。呼び出しは IO のスレッドから）。選択を取り消したら何も書かない。書き出したら成功、失敗したら失敗を、画面の下の知らせに出す。ストレージの権限は求めない（OS の選択が書き込み先を渡す）。ログの本文は、書かないもの（鍵、コード、パス、署名の値）を伏せた後の行だけで、保存でも変えない |
| 消去 | 確認の画面の後、`logs/` の全世代を消す。消した旨の 1 行を新しい世代に書く。画面の欄（メモリの直近 V55 行。X7-5-1）も消え、消した旨の 1 行だけが残る（TA-136） |

- 閲覧と共有の切り詰めは共通の関数で行う（新しい世代から読み、末尾の V51 行までを返す。V51）
- 閲覧と共有の読み取りも、ファイルへの保存と同じく、ログの書き込みと同じ executor で行い、先に投げた書き込みが済んでから読む（直列。世代送りの途中のファイルを読まない。TA-118）

- 共有と保存の直前に、「曲名が含まれる」旨の確認を 1 回出す（N1-6 の「曲名まで」を利用者に見せる）
- 共有の一時のファイルは作らず、テキストで Intent に渡す。ファイルで渡す方式（`FileProvider`）は持たない（J20（a））。Intent で渡すテキストの大きさの上限（値は未確認）は、上の切り詰めで避ける（J43）。切り詰めは単体で確かめ、実機は C-14 の 1 行（共有できた）で確かめる

### X7-6 ライセンスの表示

- 目的：OSS のライセンスの表示（N4-4。B4-7）
- 画面：S5 の「ライセンス」から開く一覧の画面。1 項目につき、部品の名前、版、ライセンスの名前。項目を選ぶと、そのライセンスの全文を表示する。依存の jar に NOTICE があれば、全文と一緒に出す（名前と URL だけにしない。review-15。X7-7）
- 元の一覧：Licensee（`app.cash.licensee`）が出力する `artifacts.json`（全依存の許諾）。Android の変種の資産への同梱（`bundleAndroidAsset`）を使い、アプリの資産（assets）に入れる。画面は読み込んで表示するだけ（J21。X1-3 の version catalog に `licensee` を足す）。`artifacts.json` は部品ごとに許諾の名前と URL を持つが、全文は持たない。画面が読む項目は実物で確かめる（未確認）
- 全文：許諾の種類（許す種類は Licensee の許可の宣言と同じ。Licensee の `identifier`（SPDX があるとき）か `url`（無いとき）で見分ける）ごとの全文のテキストを、アプリの資産の `licenses/` に同梱する。許す種類は Apache-2.0、MIT（URL で識別）、Bouncy Castle の許諾。依存を足して許す種類が増えたときは、全文も足す
- NOTICE（2 周目。review-15 の X7-7）：Apache-2.0 の依存の jar は `META-INF/NOTICE*` を持つことがある。ビルドのときに、依存の jar からこのファイルを集めてアプリの資産に同梱する（集めるのは Gradle のタスク。実行時に jar を読まない。資産の `notices/` に、NOTICE を持つ jar ごとに `<artifactId>-<版>.txt`（jar の名前と同じ）で置く）。画面では、その部品の許諾の全文の後に続けて出す。NOTICE の無い部品は全文だけを出す
- 手順：
  1. 資産の `artifacts.json` を読み、部品の名前の昇順に並べる
  2. 全文は選択されたときに読む（一覧の読み込みでは全文を読まない）。許諾の名前と URL の下に、項目の許諾の種類に対応する全文を表示する。許諾が複数なら続けて並べる。その部品の NOTICE があれば、全文の後に「NOTICE」の見出し付きで続ける。全文を読めなければ「ライセンスの全文を読み込めません」を出す
  3. 資産が読めなければ「読み込めない」を表示する（アプリを止めない）
- 外部の通信はしない（全文は同梱）

### X7-7 テストの観点

### X7 の決定（未付番）

- 画面は状態の型を ViewModel が持ち、画面は描くだけにする（X7-1-1）
- 通知のチャンネルは `sync_progress`、`sync_result`、`sync_result_quiet` の 3 つ（X7-3-1）

- ライセンスは全文と、依存の NOTICE を同梱して表示する（review-15。X7-6）
- 確認コードは shared の `formatFingerprintOfHash` で作り、端末に別の実装を持たない（review-15。X7-1-3）
