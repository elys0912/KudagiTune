## X2 itunes（M2）と XML の監視

### X2 の前提

- 引き受ける範囲：B2-1（plist の読み取り）、B2-2 の `file://` の復号、B2-3（監視と読み直し）。ファイルの実在の確認は M3 の仕事で、X2-4 の末尾で呼び出しの順だけ書く。マニフェストの組み立ては X3 と X5
- M2 は純粋な関数だけを持つ（N5-1）。入力はバイト列、出力は X2-3 の型。ファイル、時計、ログの出力に触れない。診断は結果の型に載せ、書き出すのは M3
- 値は V の番号で参照する。V5、V6、V7、V18 を使う。新しい値は各節末の「置いた値」に並べる
- キー名と型は B2-1 の表のとおり。iTunes 12.x の実物で確かめていない項目は「（未確認）」のまま持ち越す。実物で確かめた結果は試料（X2-5）に反映する

### X2-1 plist の読み手

B2-1 の「先頭から順に読む方式」を、状態機械で書く。技術は B1-4 に従い、Java の標準のプル型の XML 読み取り（StAX の見込み。未確認）を想定する。

読み取りの設定：

| 項目 | 規則 |
|---|---|
| DTD と外部実体 | 読まない。plist の `DOCTYPE` が指す外部の DTD を取りに行かない（通信の発生と実体の展開を避けるため） |
| 文字列の連結 | 1 つの要素の文字が複数の部分に分かれて届くので、要素の終わりまで連結してから使う |
| 文字参照 | 読み取りの段で戻る（B2-2 の前提）。復号の入力は戻した後の文字列 |
| 読み取りの単位 | 全体を木にしない。木にするのは、取る対象の 1 トラック・1 プレイリストの辞書の中の値だけ |

要素の対応（plist の書式。キーは `<key>`、値は次の兄弟の要素）：

| 要素 | 型 | 値の取り方 |
|---|---|---|
| `integer` | 整数 | 64 ビットの整数。範囲を超えたら、その項目は空 |
| `string` | 文字列 | 要素の文字をそのまま。空の要素は空文字列 |
| `date` | 日時 | ISO 8601 の UTC。解析できなければ空 |
| `true`、`false` | 真偽 | 内容を持たない要素の名で決まる |
| `dict`、`array` | 入れ子 | 取る対象でなければ、深さを数えて読み捨てる（下の「読み捨て」） |
| `data`、`real` | その他 | 読み捨てる。`Smart Info`、`Smart Criteria` は `data` |

状態機械（深さの数え方：開始の要素で +1、終了の要素で −1）：

| 状態 | 意味 | 次の入力 | 動作 → 次の状態 |
|---|---|---|---|
| S0 開始 | 文書の先頭 | 最上位の `dict` の開始 | → S1 |
| S1 最上位のキー待ち | 最上位の辞書の直下 | `key` が `Tracks` | → S2 |
| | | `key` が `Playlists` | → S5 |
| | | `key` が `Library Persistent ID` | 次の `string` を保存 → S1 |
| | | `key` がそのほか | 次の値を読み捨て → S1（`Date`、`Application Version` は診断用に保存） |
| S2 `Tracks` の辞書 | キーは Track ID の文字列 | `key` | Track ID を保持 → S3 |
| | | `dict` の終了 | → S1 |
| S3 トラックの辞書待ち | | `dict` の開始 | → S4。`dict` でなければ値を読み捨て、診断に数える → S2 |
| S4 トラックの項目 | B2-1 のトラックの表のキー | 取るキー | 値を型に合わせて保持。型が違えば項目は空 |
| | | 取らないキー | 値を読み捨て |
| | | `dict` の終了 | トラックを確定して一覧へ → S2 |
| S5 `Playlists` の配列 | | `dict` の開始 | → S6 |
| | | `array` の終了 | → S1 |
| S6 プレイリストの項目 | B2-1 のプレイリストの表のキー | 取るキー | 値を保持 |
| | | `Playlist Items` | → S7 |
| | | `dict` の終了 | プレイリストを確定 → S5 |
| S7 `Playlist Items` の配列 | 要素は `{ Track ID }` の辞書 | `dict` の開始 | `Track ID` の `integer` だけ取り、ほかの鍵は読み捨てて Track ID の並びに足す |
| | | `array` の終了 | → S6 |

読み捨て：

1. 読み捨てる値の開始で、深さを 0 にして数え始める
2. 開始の要素で +1、終了の要素で −1。値が 1 要素で閉じるもの（`integer`、`string`、`true`）は 1 要素で終わる
3. 深さが 0 に戻った時点で、読み捨てを終える
4. 未知のキーは読み捨てるだけで、エラーにしない。増えても壊れない（B2-1）

解決（読み取りの終わりに 1 回）：

1. トラックの確定のとき、`Persistent ID` を大文字に揃える。16 桁の 16 進でなければ「ID 無し」として扱う
2. 同じ `Persistent ID` が 2 回出たら、先のトラックを残し、後のものを捨てて診断に数える
3. `Tracks` と `Playlists` の順は仮定しない。プレイリストの `Track ID` は、文書の最後まで読んでから、`Track ID` から `Persistent ID` への対応で置き換える（B2-1）
4. 対応に無い `Track ID` は落とし、件数を診断に数える
5. 対応にあるが ID 無しのトラックは、「ID 無しの参照」として並びに残す（X2-3）。ID 無しの除外を結果に出すため

最上位の構造が違うとき（最上位が `dict` でない、構文が壊れている）は、読み取りの失敗にする。`Tracks` か `Playlists` が無ければ失敗（J21（b））。

### X2-2 `file://` の復号

B2-2 の手順 1〜6 を関数に分ける。入力は戻した後の `Location` の文字列。

| 関数 | 入力 | 出力 | 副作用 |
|---|---|---|---|
| `decodeFileUrl` | `Location` の文字列 | 場所の結果（下の表） | なし |
| `splitAuthority` | `file://` の後ろの文字列 | 権限部とパス部 | なし |
| `percentDecode` | パス部 | 復号した文字列、または失敗 | なし。厳密な UTF-8 の復号（不正なバイト列は失敗）を使う |
| `toWindowsPath` | 権限部、復号したパス | Windows のパス（`\` 区切り）、または失敗 | なし。ファイルの API は呼ばない |

場所の結果（M2 の出力のうち、1 トラックの場所を表す型）：

| 種類 | 持つ値 | 意味 |
|---|---|---|
| 場所あり | Windows のパス（文字列） | 復号に成功した |
| 場所なし | なし | `Location` が無い、または `Track Type` が `File` でない（B2-2 の「場所なし」） |
| 復号不能 | 失敗の細目（下の表） | 手順 1、3、4、5 の失敗（B2-2 の「復号不能」） |

失敗の細目（診断とログに使う。結果の一覧には出さない）：

| 細目 | 条件 |
|---|---|
| 書式の違い | 先頭が `file://` でない（手順 1） |
| ホストを直せない | 権限部が `localhost`・空以外で、`\\ホスト名\共有名\…` の形に直せない（手順 3） |
| 不正な符号 | `%` の後ろが 16 進 2 桁でない、復号したバイト列が UTF-8 として不正（手順 4） |
| ドライブ文字なし | ローカルのパスで、`/X:/…` の形でない（手順 5） |
| 制御文字 | 復号した結果に、NUL を含む制御文字がある（置いた規則） |

復号の手順（疑似手順）：

1. 先頭が `file://`（大文字小文字を区別しない）でなければ、「書式の違い」で失敗にする
2. 先頭の 7 文字を除き、最初の `/` までを権限部、その後ろ（`/` を含む）をパス部にする。`/` が無ければパス部は空で、「書式の違い」
3. パス部を `percentDecode` にかける。`+` はそのまま `+`。失敗なら「不正な符号」
4. 復号した結果に制御文字があれば「制御文字」
5. 権限部が `localhost`（大文字小文字を区別しない）か空なら、ローカルとして、パス部が `/X:/` で始まる（X は英字）ことを確かめ、先頭の `/` を外す。違えば「ドライブ文字なし」
6. 権限部がそれ以外なら、`\\` + 権限部 + パス部の `/` を `\` に直した形にする。共有名の要素（パス部の最初の要素）が空なら「ホストを直せない」
7. ローカルのパスの `/` も `\` に直して返す。復号で現れた `%2F` の `/` は区切りとして扱う（Windows のファイル名に `/` は使えないため）

境界の例（192.0.2.0/24 と `example.invalid` の範囲。曲名は合成）：

| 入力 | 結果 |
|---|---|
| `file://localhost/C:/Music/A%20B/%E6%9B%B2%231.mp3` | 場所あり：`C:\Music\A B\曲#1.mp3` |
| `file:///C:/Music/a%25b.mp3` | 場所あり：`C:\Music\a%b.mp3` |
| `file://localhost/C:/Music/a+b.mp3` | 場所あり：`C:\Music\a+b.mp3`（`+` はそのまま） |
| `file://nas.example.invalid/share/a.mp3` | 場所あり：`\\nas.example.invalid\share\a.mp3`（iTunes がこの形を書くかは未確認） |
| `file://localhost/Users/x/a.mp3` | 復号不能：ドライブ文字なし |
| `file://localhost/C:/Music/%E3%81.mp3` | 復号不能：不正な符号 |
| `file://localhost/C:/Music/a%zz.mp3` | 復号不能：不正な符号 |
| `http://example.invalid/a.mp3` | 復号不能：書式の違い |
| 空文字列 | 復号不能：書式の違い（`Location` の欠落は「場所なし」で、空文字列とは別） |

- B2-2 の手順 5 は、手順 3 の `\\` の形に当てると必ず失敗する。上の手順 5 と 6 で、ローカルにだけ当てる読み方にした（基本設計の直し 8）
- パスの長さの上限と、実在の確認は M3 が行う（X2-4）

### X2-3 読み取りの結果の型

M2 の出力。型は M2 に置く。M1 の型（マニフェスト、E）は import しないで足りる。除外の理由の列挙は M1（X3-5）が持つので、M2 は理由そのものを返さず、判定の材料を返す。

`LibraryReadResult`（M2 の出力）：

| 項目 | 型 | 必須 | 意味 |
|---|---|---|---|
| `libraryPersistentId` | string | 任意 | `Library Persistent ID`（大文字に揃える）。無ければ空（B2-4 の `library_id` の暫定の扱いは M3） |
| `tracks` | `LibraryTrack` の一覧 | 必須 | ID を持つトラック。`Persistent ID` で一意 |
| `unidentifiedTracks` | `UnidentifiedTrack` の一覧 | 必須 | ID 無しのトラック（曲名、アーティストだけ）。位置の番号を持つ |
| `playlists` | `LibraryPlaylist` の一覧 | 必須 | B2-1 の除外の規則で除外する前の全件。除外の判定は下の `kind` に持つ |
| `diagnostics` | `ReadDiagnostics` | 必須 | 診断の件数 |

`LibraryTrack`：

| 項目 | 型 | 必須 | 意味 |
|---|---|---|---|
| `persistentId` | string | 必須 | 大文字 16 桁の 16 進 |
| `location` | 場所の結果 | 必須 | X2-2 |
| `trackType` | string | 任意 | `Track Type` の値 |
| `name`、`artist`、`album`、`albumArtist` | string | 任意 | 無ければ空 |
| `trackNumber`、`discNumber` | integer | 任意 | 無ければ空 |
| `totalTimeMs` | long | 任意 | `Total Time` |
| `kind` | string | 任意 | `Kind` |
| `isProtected` | boolean | 必須 | 無ければ偽 |

- 拡張子とファイル名は、M2 は持たない。M3 が `場所あり` のパスから取る（B2-4 の `file_name`、`extension`）
- `Size` と `Date Modified` は読み捨てる（J21（b）。B2-1 の直しは基本設計の直し 9）

`UnidentifiedTrack`：

| 項目 | 型 | 必須 | 意味 |
|---|---|---|---|
| `name`、`artist` | string | 任意 | 結果の一覧（B2-2 の「ID 無し」）に出す |

`LibraryPlaylist`：

| 項目 | 型 | 必須 | 意味 |
|---|---|---|---|
| `persistentId` | string | 必須 | `Playlist Persistent ID`。無いプレイリストは落とし、診断に数える |
| `name` | string | 必須 | 無ければ空 |
| `parentPersistentId` | string | 任意 | `Parent Persistent ID` |
| `kind` | 通常、除外の印 | 必須 | `Master` が真、`Distinguished Kind` を持つ、`Folder` が真のいずれかなら除外の印と、その理由の種類（B2-1 の決定（未付番）。選べない。J15） |
| `items` | `TrackRef` の一覧 | 必須 | 順序付き。重複を残す。`Playlist Items` が無ければ空 |

`TrackRef`：次のどちらか。

| 種類 | 持つ値 | 意味 |
|---|---|---|
| 識別あり | `persistentId` | `tracks` のトラックを指す |
| 識別なし | `unidentifiedTracks` の位置 | ID 無しのトラックを指す |

`ReadDiagnostics`（件数。ログに書くのは M3）：

| 項目 | 意味 |
|---|---|
| `trackCount`、`playlistCount` | 読んだ件数 |
| `droppedTrackRefs` | `Tracks` に無い `Track ID` で落とした件数（B2-1） |
| `duplicatePersistentIds` | 重複した ID で落としたトラックの件数 |
| `malformedEntries` | 型が違うなどで読めなかった項目の件数 |
| `locationFailures` | 復号不能の細目ごとの件数 |
| `applicationVersion`、`xmlDate` | 診断用。無ければ空 |

読み取りの失敗の型（`LibraryReadError`）：

| 種類 | 条件 | M3 の扱い |
|---|---|---|
| 構文の不正 | XML が壊れている | 読み直し（X2-4） |
| 構造の違い | 最上位が辞書でない、`Tracks` か `Playlists` が無い | 読み直し。同じ扱い |
| 読み取りの失敗 | バイト列を読めない（M3 が渡す入力の失敗） | 同じ。入力の失敗は M3 が包んで渡す |

- 除外の規則（B2-2 の表）のうち、M2 が持つ材料は 場所なし・復号不能・ID 無し・保護の 4 つ。理由の最終の決定（保護の判定、実在しない、読めない）はマニフェストを組む M3 が M1 の型で行う（X3-5 に依頼）
- M2 の出力は、ファイルの実在の確認の前の状態（B2-1）

### X2-4 監視と読み直し（M3 側）

B2-3 の動作を、M3 の部品に分ける。M2 を呼ぶのも M3。

| 部品 | 入力 | 出力 | 副作用 |
|---|---|---|---|
| `LibraryWatcher` | XML のフォルダ、ファイル名 | 「変わったかもしれない」の通知（イベントの種別は区別しない） | フォルダの監視の登録。作成、変更、取りこぼし（OVERFLOW）を受ける |
| `StabilityWaiter` | XML のパス、V18 | 安定した（`true`）、または待ち直し | サイズと更新日時を読む。変われば待ちを最初からにする |
| `LibraryLoader` | XML のパス、読み込み済みの更新日時 | `LibraryReadResult` または `LibraryReadError` | ファイルを開いて M2 に渡す。V6 の再読を行う |
| `LibraryHolder` | `LibraryLoader` の結果 | 最後に読めた結果、その更新日時、状態（正常、古い、読めない） | メモリに持つ。画面とサーバーが読む |
| `LibraryRefresher` | 要求の種別（監視、起動、要求の時） | 読み直しの完了 | 読み直しを 1 本に直列にする |

読み直しの制御（疑似手順）：

1. 起動のとき、`LibraryLoader` を 1 回呼ぶ（B2-3 の「起動時」）
2. `LibraryWatcher` から通知を受けたら、`StabilityWaiter` を呼ぶ。通知が重複して届いても、待ちの中の通知は 1 つに畳む
3. 安定したら `LibraryLoader` を呼ぶ。読み取りの最中にさらに通知が来たら「再読の印」を立て、読み終えた後にもう 1 回読む（B2-3）
4. 失敗したら、V6 の間隔で待って読み直す。回数を超えたら諦める
5. 諦めたとき：`LibraryHolder` の最後の結果は残す。状態を「読めない」にして、画面へ警告を出す（B4）。サーバーはマニフェストの要求に E4 で応える。最後に読めた結果で応えない（B2-3 の決定（未付番））
6. 成功したら、`LibraryHolder` を新しい結果に替え、状態を「正常」に戻す。読み取りの中は、古い結果を触らない（途中の状態を見せない）
7. 要求の時（P1。B2-3）：XML の更新日時を取り、`LibraryHolder` の値と違えば、1〜4 と同じ制御で読み直してから応える。このときの安定待ちは省かない
8. 要求の時の読み直しは、進行中の読み直しがあれば、それが終わるのを待ち、同じ結果を使う（二重に読まない）

`WatchService` の使い方：

| 項目 | 規則 |
|---|---|
| 登録 | XML のフォルダを、作成と変更の 2 種で登録する（B2-3）。ファイル名で絞る |
| 絞り込み | 通知のファイル名が XML のファイル名と一致するときだけ受ける（大文字小文字を区別しない。Windows のため） |
| 取りこぼし | OVERFLOW を受けたら、XML の更新日時を取り直して判定する（通知の有無に頼らない） |
| 重複 | Windows で 1 回の書き込みに複数の通知が出る可能性は未確認。`StabilityWaiter` と畳み込みで吸収する |
| フォルダの消失 | 監視の登録が無効になったら、V18 の間隔でフォルダの存在を確かめ、戻ったら登録し直して 1 回読む（置いた規則） |
| ネットワーク上のフォルダ | 通知が来ない場合の対処は、要求の時の更新日時の確認で足りる（B2-3）。常時の定期の確認は持たない |

古さの警告（B2-3、V5）：

1. 読み取りに成功するたび、XML の更新日時と現在の時刻の差を V5 と比べる
2. 超えていれば、`LibraryHolder` の状態を「古い」にする。文は「XML の更新が古い」とし、原因を書かない
3. 状態は、正常、古い、読めない（最後の結果あり）、読めない（結果なし）の 4 つ。画面の表示は X5-5

ファイルの実在の確認を呼ぶ順（マニフェストを作るとき。B2-2）：

1. `LibraryHolder` の結果を取る。選んだプレイリスト（B4 の選択）に入る `TrackRef` だけを対象にする
2. 識別あり、かつ場所ありのトラックについて、実在と読み取りを確かめ、サイズと更新日時を取る（M3）
3. 判定の結果を X3-5 の理由に当てて、除外の一覧とプレイリストの並びを作る。除外の曲は並びから外す（B2-2）

### X2-5 テストの観点

試料は、すべて匿名の合成 XML。実物の曲名・パス・ID を使わない。試料は M2 のテストの資源に置き、次の 6 種を作る。

| 試料 | 中身 | 見る点 |
|---|---|---|
| 標準 | トラック数曲、プレイリスト 2 本（通常 1、Master 1）、全キー | B2-1 の表のとおりに取る |
| 欠損 | `Persistent ID`、`Location`、`Playlist Items`、`Name` を欠く | 空で持つ。補わない。ID 無しは別の一覧へ |
| 未知のキー | 表に無いキー（入れ子の辞書と配列を含む）をトラックとプレイリストに足す | 読み捨てて、取る項目に影響しない |
| スマート | `Smart Info`、`Smart Criteria`、展開済みの `Playlist Items` | 条件を読まず、並びだけ使う |
| 参照の欠け | `Tracks` に無い `Track ID`、重複した `Persistent ID`、同じ曲を 2 回含む並び | 落とす・残す件数が診断と一致 |
| 順序 | `Playlists` が `Tracks` より前の文書 | 結果が標準と同じ |

境界の値（1 つずつ単体のテストにする。基準は「期待する結果」の列）：

| 対象 | 入力 | 期待する結果 |
|---|---|---|
| `Persistent ID` | 小文字、15 桁、17 桁、16 進以外 | 小文字は大文字へ。ほかは ID 無し |
| `Integer` | 64 ビットを超える値 | その項目は空 |
| `date` | 不正な書式 | その項目は空 |
| 構文 | 閉じていない要素、空の文書、BOM 付き | 前 2 つは構文の不正。BOM 付きは成功 |
| DTD | 外部の DTD を指す `DOCTYPE` | 取りに行かず成功（通信が発生しない） |
| 文字参照 | `&amp;`、`&#38;`、`&lt;` を含む名前と `Location` | 戻した後の文字列で復号（X2-2） |
| 深い入れ子 | 取らないキーの値に深さ 50 の入れ子 | 読み捨てて、後続のキーを読める |
| 復号 | X2-2 の境界の例の全件 | 表の結果と一致 |
| 復号 | `%E6%9B%B2` の途中で切れたバイト列、`%00` | 不正な符号、制御文字 |
| 規模 | 合成で数万トラック、プレイリスト数百本 | V7 の目標の時間内（時間の測り方は CI の環境差に注意。余裕を持つ。X1 の CI の節と整合） |

- 読み直し（M3）のテストは、実際の待ちを使わず、時刻と待ちを差し替える。確かめる点：安定待ちの途中で変化したら待ち直す、再読の印で 1 回多く読む、V6 の回数で諦める、諦めた後も最後の結果が残る、要求の時の更新日時の差で再読する
- `WatchService` そのものは実ファイルの一時フォルダで確かめる薄いテスト。作成のみ、変更のみ、置き換え（一時ファイルへ書いて改名）の 3 つの書き方で、通知が最低 1 回来ること。Windows の重複の数は固定しない
- 実機（C-1〜C-9 の表）で確かめるもの：iTunes が XML をどう書き換えるか、実物のキーと値（「確かめた事実」の未確認の項目）

### X2 の決定（未付番）

- `Playlists` を先に、`Tracks` を後に置く文書でも読めるよう、`Track ID` の置き換えは文書の最後まで読んでから行う。根拠：キーの順は公式に定めた文書が見つからず、仮定すると誤る
- 外部の DTD と実体を読まない。根拠：plist の `DOCTYPE` が外部の URL を指すため、通信の発生と実体展開を避ける
- ID 無しのトラックは、M2 が別の一覧で返し、プレイリストの並びに「識別なし」の参照として残す。根拠：B2-2 の「ID 無し」を結果に出すには、並びの中の位置を落とせない
- 要求の時の読み直しは、進行中の読み直しを待って結果を共有し、二重に読まない。根拠：複数の端末の要求が重なっても、1 回の読み取りで足りる
