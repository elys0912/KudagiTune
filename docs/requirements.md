## 機能要件

### ライブラリの読み取り（F1）

| # | 要件 |
|---|---|
| F1-1 | 入口は iTunes Music Library.xml（plist 形式）とする。COM は使わない |
| F1-2 | iTunes 12.x では、設定「iTunes ライブラリ XML を他のアプリケーションと共有」（日本語名は未確認）を有効にしたときに自動で更新される XML を読む |
| F1-3 | Apple Music アプリ（Windows）は最初の版では対象にしない。書き出しの機能が無い見込み（Q11、D1）。手段が見つかったときに足す |
| F1-4 | トラックから取る項目：ID、Persistent ID、ファイルの場所（`file://` URL）、総時間、曲名、アーティスト、アルバム、アルバムアーティスト、トラック番号、ディスク番号、Kind、Protected。サイズと更新日時は XML の値を使わず、実ファイルの値を使う（技術は基本設計） |
| F1-5 | プレイリストから取る項目：名前、順序付きのトラック ID。スマートプレイリストは XML に入っている展開済みの結果をそのまま使い、条件は解釈しない |
| F1-6 | `file://` URL を復号して、PC 上のファイルのパスに直す。日本語名と記号を含むパスも扱う（技術は基本設計） |
| F1-7 | iTunes の XML の更新を監視し、更新されたら再読み込みする。読めなかったとき（書き込みの途中など）は少し待って読み直す（回数は暫定） |
| F1-8 | XML の更新日時が古いときは、PC の画面で警告する。「古い」の基準は暫定 |
| F1-9 | 再生回数と評価は読まない。iTunes への書き戻しはしない（一方向） |
| F1-10 | ファイルの場所が無いか、ファイルが実在しないトラック（iCloud の未ダウンロード、配信の曲）は同期の対象から外し、結果に一覧で示す |

### 接続とペアリング（F2）

| # | 要件 |
|---|---|
| F2-1 | 3 方式（同一 LAN の Wi-Fi、Tailscale、USB）を、端末が 1 つの host:port へつなぐ形に揃える。サーバーは 1 つで、方式ごとの違いは接続先の決め方だけにする |
| F2-2 | 同一 LAN では、PC が mDNS で自分を広告し、端末が NSD で見つける |
| F2-3 | Tailscale では、PC の MagicDNS 名を端末へ渡す。ペアリング時に PC が自分の名前を表示し、手入力を省く。名前を取得できないときは、利用者が Tailscale の管理画面で調べて入力する（Q13）。MagicDNS 名が Android から引けるかは確かめる（Q5 の実物の確認 4） |
| F2-4 | USB では、端末の USB テザリングで PC に IP を配り、LAN と同じサーバーへつなぐ。adb は使わない（D7、Q2） |
| F2-5 | 初回に PC が 6 桁のペアリングコードを表示し、端末で入力する。端末は共有の鍵と PC の証明書を保存する（trust on first use）。コードそのものは送らない。両側がコードから導いた鍵で互いを確かめる（方式は基本設計、Q5） |
| F2-6 | ペアリング済みの端末だけを配信の相手にする。鍵なしの要求には、LAN の中でも配信しない |
| F2-7 | ペアリングの解除を、PC と端末のどちらからでもできる |

### 同期（F3）

| # | 要件 |
|---|---|
| F3-1 | 端末は、PC が XML から作ったマニフェスト（選択したプレイリストに入る曲の集合と、プレイリストの定義）を取得する |
| F3-2 | 曲の同一性は Persistent ID で判定する。変更の検知はサイズと更新日時で行う（ハッシュを足すかは基本設計） |
| F3-3 | 端末は自分の同期状態とマニフェストを突き合わせ、差分を 3 種（足す、置き換える、消す）に分ける。差分は選んだプレイリスト全体の曲の集合で取る。消すのは、どの選んだプレイリストにも入らなくなった曲 |
| F3-4 | 曲は 1 曲ずつ取得する。中断した曲は Range 指定で続きから再開する |
| F3-5 | 消すのは、自分の同期状態にある曲だけとする。アプリを入れ直した後は、以前に置いた曲を「自分が置いた」と扱わない。消すときだけ利用者の同意の画面を出す（D14）。入れ直した後は、設定の「以前の曲の整理」で、以前に置いた曲と m3u8 を利用者が選んで消せる。整理のときだけ音声の読み取りの権限を求める |
| F3-6 | 起動は、端末のアプリでの手動と、自動の 2 つとする。自動は、従量制でないネットワークにつながっている間、周期で起動し、ペアリング済みの PC に届かなければ何もせず終わる（D13、Q6。つながった瞬間には起動しない。周期は基本設計）。SSID は見ない |
| F3-7 | 進み具合（件数、容量、現在の曲）は、端末の通知に出す |
| F3-8 | 途中で失敗したときは、取得済みの曲を残し、同期状態は完了した曲の分だけ更新する。次回の同期は続きから差分を取り直す。初回の同期は数回に分かれうる |
| F3-9 | 形式の変換（ALAC から AAC など）は行わず、ファイルをそのまま送る。変換は PC 側に置く余地だけ残す |
| F3-10 | 消す件数の確認（全消しの防止）：「消す」が閾値を超えるとき、同期状態の曲の全部に当たるとき、別のライブラリに付け替えたとき、PC で見つからないプレイリストがあるときは、確認が要る扱いにする（閾値は暫定、基本設計）。手動の同期は、実行の前に利用者へ件数を見せて確認し、取り消したときは消すことだけを飛ばして同期を続ける。自動の同期は、確認が要る扱いのときだけ消すことを飛ばし、通知で知らせる。確認が要らないときは、自動でも消す。F3-5 の同意の画面（OS の画面）とは別 |

### 端末側の配置（F4）

| # | 要件 |
|---|---|
| F4-1 | 曲の保存先は `Music/<アプリ名>/<アーティスト>/<アルバム>/<曲>` とする。ファイル名に使えない文字は置き換える。同名の別トラック（Persistent ID が違う）と衝突したら、Persistent ID の一部をファイル名に足す |
| F4-2 | m3u8 はプレイリストごとに 1 ファイルを書く。形式は、曲のパスを相対パスにし、文字コードを UTF-8 にする |
| F4-3 | m3u8 を置くことで、MediaStore のプレイリストにも反映されることを狙う。`MediaStore.Audio.Playlists` への直接書き込みは使わない（Q4） |
| F4-4 | 変わったときに m3u8 を作り直す（差分が空で、PC の曲とプレイリストの内容が前回の完了と同じときは作り直しを省く）。消した曲は m3u8 からも外す |
| F4-5 | 利用者が別に入れた曲とプレイリストには、読み取りも変更もしない。例外は F3-5 の「以前の曲の整理」で、利用者が開いたときだけ、音声の読み取りの権限を求め、`Music/<アプリ名>/` の配下の曲と m3u8 を一覧する。消すのは利用者が選んだものだけ |

### PC 側の画面と常駐（F5）

| # | 要件 |
|---|---|
| F5-1 | PC のアプリはトレイに常駐し、画面は 1〜2 枚とする |
| F5-2 | 同期するプレイリストを、利用者が一覧から選ぶ |
| F5-3 | 接続中の端末と、その端末の最後の同期（日時、結果）を表示する |
| F5-4 | ペアリングコードを表示する。コードは使用後と一定時間後に無効にする（時間は暫定） |
| F5-5 | XML の場所を設定する。iTunes 12.x では既定の場所を初期値にする |
| F5-6 | XML の更新が古いときの警告（F1-8）を表示する |

### 運用（記録・エラー・更新）（F6）

| # | 要件 |
|---|---|
| F6-1 | PC と端末は、それぞれ動作のログを持つ。ログは端末の中と PC の中に置き、利用者の操作による共有を除いて外へ送らない。ログは大きさに上限を設け、古い分から消す（値は暫定） |
| F6-2 | 失敗は、原因の種類（接続できない、鍵が合わない、容量不足、XML が読めない、ファイルが無い）を分けて利用者に見せる |
| F6-3 | 設定（XML の場所、選択したプレイリスト、ペアリング済みの端末）は、PC では利用者のユーザー領域に、端末ではアプリの内部領域に保存する |
| F6-4 | アプリ内で更新の確認（外への通信）はしない。新しい版は GitHub の Releases の案内に任せる（D12） |
| F6-5 | PC の画面の言語は日本語とする（暫定） |

## 非機能要件

### セキュリティ（N1）

| # | 要件 |
|---|---|
| N1-1 | 通信は自己署名の TLS とする。端末はペアリング時に受け取った PC の証明書を固定し、それ以外の証明書では接続しない |
| N1-2 | 要求はペアリングで共有した鍵で署名する。PC は署名の合わない要求を拒否する。再送を防ぐ値（時刻や一回限りの値）を署名に含める（技術は基本設計） |
| N1-3 | ペアリングコードの入力は、試行回数に上限を設ける。上限を超えたら、そのコードを無効にして作り直す（回数と待ち時間は暫定） |
| N1-4 | 共有の鍵は、PC では OS が利用者ごとに保護する形（DPAPI）で暗号化して保管し、端末ではアプリの内部領域に保管する。平文のファイルに置かない |
| N1-5 | LAN の中でも、認証なしに曲とマニフェストを配信しない |
| N1-6 | 通信と画面に出す個人情報は曲名までとする。PC のログにはファイルのパスを出してよい（PC の利用者のものであるため）。鍵とペアリングコードはどこにも出さない |
| N1-7 | 配信するのは選択したプレイリストの曲だけとし、PC 上のほかのファイルは配信しない。曲の取得はマニフェストの ID だけで指定し、パスを受け取らない |

### 性能と容量（N2）

| # | 要件 |
|---|---|
| N2-1 | 数千曲、数十 GB の同期を想定する |
| N2-2 | 転送は 1 曲ずつとし、中断から再開できる（F3-4）。再開で転送済みの部分を取り直さない |
| N2-3 | XML の読み取りは、数万トラックで数秒を目標にする（暫定） |
| N2-4 | 同期の前に、差分の合計サイズと端末の空き容量を比べる。足りないときは同期を始めず、不足分を表示する |
| N2-5 | 差分が無く、PC の曲とプレイリストの内容が前回の完了と同じときの同期は、手動なら P1 の取得と結果の記録だけ、自動なら到達確認だけで終わる（m3u8 の作り直しと消す処理を省く。J37） |
| N2-6 | 転送は前面サービスで行う。OS の実行時間の上限（Android 15 以降は dataSync が 24 時間に合計 6 時間）に当たったら中断し、次回に続きを行う（版ごとの制約は基本設計） |

### 互換性（N3）

| # | 要件 |
|---|---|
| N3-1 | iTunes 12.x の XML を読める。Apple Music アプリは保留（D1、Q11） |
| N3-2 | PC は Windows 10 と 11 で動く |
| N3-3 | Android の最低版は 11 とする。Scoped storage と、メディアスキャンによる m3u の索引を前提にするため（Q4） |
| N3-4 | m3u8 が、主なプレイヤー（Poweramp、Musicolet、標準のプレイヤー）で読めること。実機で確かめる（Q4） |
| N3-5 | 曲のファイル形式は、ライブラリにあるものをそのまま送る。端末で再生できない形式は同期の結果に一覧で示す。旧い DRM 付きの AAC（.m4p）も再生できない形式に含める |

### 配布とライセンス（N4）

| # | 要件 |
|---|---|
| N4-1 | PC の実行物は GitHub の Releases で配る。形は zip（Q12）。コード署名なしは暫定 |
| N4-2 | Android は APK を GitHub の Releases で配る。Play ストアは将来（D12、Q12） |
| N4-3 | adb は同梱しない。platform-tools のライセンスの確認は不要（D7） |
| N4-4 | 使う OSS のライセンスを、アプリ内に表示する |

### 保守とテスト（N5）

| # | 要件 |
|---|---|
| N5-1 | shared（マニフェスト、差分、m3u8、ペアリングと署名）と itunes（XML の読み取り、URL の復号）は、外部に依存しない純粋な関数にする。テストの中心はこの 2 つとする |
| N5-2 | desktop と android は薄く保ち、判断を shared と itunes に置く |
| N5-3 | 実機でしか確かめられないもの（mDNS、USB テザリング、MediaStore への反映、各プレイヤーでの読み込み、Tailscale の名前解決）は、確認の表を別に作って記録する |
| N5-4 | 1 つの repo を Gradle のマルチプロジェクトで構成する（モジュールの分け方は基本設計） |
