playlist-sync-fox 設計の視覚資料

概要設計（第 2 稿）、基本設計・詳細設計（第 5 稿）、テスト計画（第 3 稿）まで区切り（2026-11-06。review-13 を反映）

iTunes（12.x）のプレイリストを曲ごと Android へ。PC → 端末の一方向。

2. 接続 3 方式

方式端末がつなぐ先発見の仕方備考
同一 LAN の Wi-FiPC の host:portmDNS（PC が広告）／NSD（端末が発見）。自動で見つかる3 方式とも 1 つの TCP に揃える
TailscalePC の host:portMagicDNS 名を端末に手入力（PC の画面に表示される）外出先からの同期に使う。名前が引けることは確認済み（2026-11-05）
USB テザリングPC の host:portmDNS で見つかる。見つからなければ PC の画面の IP（例：192.0.2.10）を手入力LAN と同じ経路。adb は使わない

3. ペアリングの流れ

PC の画面に 6 桁のコードを出し、端末に入力する。コードは通信に流さない。SPAKE2 で両側が同じ署名用の鍵 K を導く。

0 コード表示PC が 6 桁を表示。端末で入力
▶
1 P5 開始端末 → PC：端末 ID、表示名、SPAKE2 の値 X
▶
2 P5 応答PC → 端末：PC の ID、値 Y（コード非表示中は拒否）
▶
3 P6 確認端末 → PC：端末の確認の印
▶
4 P6 応答PC → 端末：PC の確認の印
▶
5 鍵を導く両方の印が合えば成功。共有の秘密から K
  • PC と端末の画面に「指紋」（PC の公開鍵のハッシュ）が出る。見比べて確かめられる。
  • P6 の印が合わない試行だけ数える。上限を超えたらコードを作り直す。
  • 端末を入れ直したら、PC 側で「ペアリングを解除」してから再ペアリングする。

4. 同期の流れ

1 到達確認（P3）PC に届くか。差分なしの判定にも使う
▶
2 マニフェスト（P1）選んだプレイリストの曲の集合と定義
▶
3 差分足す・置き換える・消す
▶
4 容量足りなければ始めない（不足分を表示）
▼
5 1 曲ずつ取得（P2）Range で再開
▶
6 m3u8 を書く端末の索引で MediaStore へ
▶
7 消す自分が置いた曲だけ。多いときなどは確認あり
▶
8 結果の報告（P4）PC の画面に表示

同期全体の失敗（E1・E2・E3・E4・E6・E7）の後では「消す」を実行しない。自動の同期は、消す件数が多いときなどだけ消さず、通知で知らせる。

5. API と失敗の種類

共通：HTTPS、パスの先頭に /v1。P1〜P4 は署名が要る。

P名前メソッドとパス署名
P1マニフェストの取得GET /v1/manifest要
P2曲の取得（Range 対応）GET /v1/tracks/{persistent_id}要
P3到達確認GET /v1/digest要
P4結果の報告POST /v1/reports要
P5ペアリングの開始POST /v1/pairing/start不要
P6ペアリングの確認POST /v1/pairing/confirm不要

失敗の種類 E1〜E9

E名範囲
E1接続不可同期全体
E2鍵不一致同期全体
E3容量不足同期全体
E4XML 不可同期全体
E5ファイル無し曲単位
E6途中切断同期全体
E7時間上限同期全体
E8マニフェストが古い曲単位
E9端末の書き込み失敗曲単位

6. 端末の置き場

Music/
└─ playlist-sync-fox/
   ├─ <プレイリスト名>.m3u8        ← m3u8 は直下に、プレイリストごと
   └─ <アーティスト>/
      └─ <アルバム>/
         └─ 曲のファイル
消すのは、このアプリが置いた曲だけ。利用者が別に入れた曲には触れない。入れ直した後は、以前の曲を「自分が置いた」と扱わない。

7. 決めたこと D1〜D14

ID項目決めたこと
D1対応するライブラリ最初の版は iTunes 12.x だけ。入口は iTunes Music Library.xml で、COM は使わない。Apple Music アプリ（Windows）は書き出しの機能が無い見込みのため保留（Q11）
D2同期の向きPC から端末への一方向のみ。再生回数と評価の書き戻しはしない
D3端末側の反映m3u8 を正とし、MediaStore へは端末の索引で反映する
D4言語Kotlin。共有部分は Kotlin Multiplatform
D5名前と置き場仮名は playlist-sync-fox。設計は portfolio の notes、repo 作成時に docs/ へ移す
D6役割PC がサーバー、端末がクライアント（pull）。同期するときだけ接続する
D7接続方式LAN の Wi-Fi、Tailscale、USB の 3 方式を 1 つのサーバーへの TCP に揃える。USB は USB テザリング。adb は同梱しない
D8認証初回に PC が出すペアリングコードを端末へ入力。鍵と PC の証明書を端末が保存（trust on first use）。LAN の中でも鍵なしでは配信しない
D9端末側の削除自分が置いた曲だけを消す。利用者が別に入れた曲には触れない
D10形式の変換最初の版では行わない。変換を PC 側に置く余地だけ残す
D11端末の数最初の版は 1 台。端末の識別子の列を持たせ、後で増やせる形にする
D12配布最初は GitHub で公開（repo は最初 private、公開前に public）。配布物は Releases。Play ストアは将来
D13自動起動従量制でないネットワークにつながっている間、周期で起動。ペアリング済みの PC に届かなければ何もせず終わる。SSID は見ない
D14入れ直しの後以前に置いた曲を「自分が置いた」と扱わない。消すときだけ利用者の同意の画面を出す
